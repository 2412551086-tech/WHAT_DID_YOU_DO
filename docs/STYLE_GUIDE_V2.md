# 《你今天干啥啦》UI Design System V2.1

> 适用范围：iOS SwiftUI、Figma 原型、AI 生图提示词、人物与家务美术资产。  
> 视觉依据：当前登录页、`style.md`、现有 DesignSystem，以及 2026-07 完成的产品视觉决策。  
> 核心原则：**产品性是基线，漫画负责记忆，系统交互与局部玻璃负责轻盈。**
>
> 2026-08-04 实现说明：主导航第一项为“本周战况”。家务库使用四主题；月报使用主题圆环与家务大类分段条；个人页支持家庭名称编辑和成员详情。本文的页面规范以这些已落地能力为准。

## 0. 已确认的设计方向

### 0.1 风格配比

- 全局以产品性方案 B 为基线。
- 登录页可以使用更强的漫画表现；记录页与个人页更克制、更接近系统体验。
- 漫画感来自人物、家务图形、贴纸和构图，不依赖漫画字体、粗重 UI 边框或持续动画。
- 页面约 80% 使用白色或奶油色，彩色只用于主卡、状态和局部强调。
- 每个页面最多设置一张视觉主卡，不把所有信息都做成悬浮彩色卡。
- 不为四个 Tab 绑定固定分区色，统一使用全局语义色。
- MVP 只支持浅色模式；深色模式需要独立设计后再开放。

### 0.2 页面视觉强度

| 页面 | 漫画感 | 产品性 | 克制/系统感 | 说明 |
| --- | ---: | ---: | ---: | --- |
| Login | 90% | 10% | 0% | 品牌首屏，可使用完整家务大战插画 |
| 本周战况 | 30% | 55% | 15% | 家庭积分和动态优先，不放全身人物 |
| 记一下 | 10% | 65% | 25% | 家务网格是内容主体 |
| 耗时 Sheet | 0% | 35% | 65% | 系统 Sheet、滚轮和玻璃材质优先 |
| 月度战报 | 30% | 55% | 15% | 冠军人物是一页唯一强视觉 |
| 我的 | 5% | 45% | 50% | 身份主卡之外使用安静分组列表 |

### 0.3 五个品牌锚点

所有页面至少保持以下识别要素中的四项：

1. 奶油白画布。
2. 系统圆角粗体标题。
3. 轻量深色轮廓。
4. 一处明确的语义强调色。
5. 同一套家庭人物形象与头像裁切。

爆炸框、速度线和拟声词不是必选品牌锚点，只允许出现在 Login、空状态或极少量战报贴纸中。

## 1. 品牌定位

### 1.1 视觉关键词

- 轻量新粗野主义漫画风
- 奶油纸张与白色内容面
- 高对比但不过度铺色
- 细黑轮廓与局部贴纸感
- 轻阴影、悬浮感与系统玻璃
- 家庭战报、功劳簿、排行榜
- 幽默、年轻、亲密、不过度低幼
- 真实可用的 iOS 产品界面

### 1.2 情绪与用户感受

| 目标 | 设计表达 |
| --- | --- |
| 有趣 | 人物动作、家务道具、短战报文案 |
| 轻盈 | 大面积留白、细描边、轻阴影、局部玻璃 |
| 公平 | 清楚展示成员、家务、耗时、积分和统计范围 |
| 亲密 | 家庭人物、身份称呼、点赞头像 |
| 有成就感 | 大数字、奖章金、排名和即时反馈 |
| 可信赖 | 系统字体、原生导航、明确状态和可预测操作 |

用户第一眼应觉得产品有记忆点；持续使用时则应觉得清楚、安静、不会累。

### 1.3 文案语气

- 品牌文案可以幽默，功能文案必须克制。
- 幽默文案只用于登录页、主卡、空状态、月报总结和完成反馈。
- 每屏最多一句明显的幽默文案。
- 按钮、错误、审核、删除确认和设置项使用直接语言。
- 不使用羞辱、性别刻板印象或制造真实家庭矛盾的文案。

推荐：

- “今天这活，到底谁干了？”
- “功劳已入账。”
- “本月暂居第一。”
- “本月战局待开启。”

避免：

- “最懒成员”
- “谁都没干活”
- “拖后腿排行榜”

### 2.4 使用约束

- 白色与奶油色合计占页面约 80%。
- 每屏最多一个主强调色和一个辅助色。
- 一张卡片最多使用一种大面积强调色。
- 品牌亮黄不是页面背景，只用于主操作和关键高光。
- 奖章金只用于冠军、奖章和月度荣誉，不替代普通黄色按钮。
- 珊瑚红只表达错误、拒绝和删除。
- 人物固定色只跟随人物，不代表页面、权限或状态。
- 状态不能只靠颜色表达，必须同时提供文字或图标。
- 彩色浅底上的正文统一使用 `ink`，不在亮黄、天蓝或薄荷绿上使用白色小字。

## 3. Typography

### 3.1 字体策略

- 所有 UI 使用 iOS 系统字体，不引入漫画字体。
- 品牌和页面标题使用系统圆角设计 `Font.Design.rounded`。
- 正文、表单和设置使用系统默认设计。
- 数字使用等宽数字，避免积分刷新时抖动。
- 字距保持 `0`，不使用负字距。
- 支持 Dynamic Type、Bold Text 和辅助功能字号。

### 3.2 字体层级

| 角色 | 基准 | 字重 | 说明 |
| --- | ---: | --- | --- |
| 登录品牌标题 | 40 pt | Black Rounded | 仅登录品牌首屏 |
| 系统 Large Title | 34 pt | Black Rounded | 本周战况、记一下、月度战报 |
| 卡片标题 | 20 pt | Bold Rounded | 主卡和分组标题 |
| 关键数字 | 28-36 pt | Black Rounded | 家庭总积分、月度积分 |
| 正文 | 17 pt | Regular / Semibold | 动态与表单 |
| 标签 | 15 pt | Semibold | 状态、身份、分类 |
| 辅助信息 | 12-13 pt | Medium | 时间与次级数据，不低于 11 pt |

### 3.3 标题规则

- Login 保留独立漫画品牌大标题。
- 本周战况、记一下、月度战报采用系统 Large Title 结构。
- “我的”页取消顶部 Large Title，直接以横向身份主卡开场。
- 次级页面使用系统紧凑导航标题，例如“加入申请”“家庭动态”。
- 功能页标题周围不放爆炸框、速度线或贴纸群。
- 月份、排序、设置等工具放进轻量玻璃工具按钮。

## 4. Character System

### 4.1 MVP 资产范围

- 当前 MVP 使用 13 个同世界观的固定成员形象，包括 12 个人物和 1 个家庭机器人。
- 每个成员均提供透明背景全身立绘和统一裁切的头像。
- 页面必须优先复用 `design-assets/Final_product/01-characters/current/` 中的现有素材，不得为同一成员临时生成不一致的新形象。
- 动作立绘只用于少量明确场景；常规表单、动态、排行榜和个人页使用固定全身立绘或头像。
- 暂不制作换装、道具组合和深度角色设定。
- 人物形象与家庭身份独立，不能把某个角色绑定为“老公”或“老妈”。

### 4.2 统一造型规则

- 1:4 头身比。
- 中度抽象、极简五官。
- 12 个人物在性别表达、肤色、体型和发型上保持多样性；机器人作为中性家庭成员形象。
- 发型、轮廓和固定服装主色承担识别功能。
- 插画使用 2.5-3 pt 等效深色轮廓，UI 裁切不额外叠加粗黑圈。

- 创建家庭和申请加入时使用横向三卡轮播：中间为当前可选择的完整立绘，左右各显示一张缩小预览。
- 用户通过左右滑动切换 13 个成员形象，页面显示当前位置，例如 `7 / 13`。
- 中间选中卡使用人物主色的低饱和浅底、1.5 pt 轻描边、柔和悬浮阴影和勾选状态。
- 左右预览卡降低尺寸和视觉权重，但不得过度模糊或降低到不可识别。
- 轮播需要支持拖动、分页吸附、清楚的选中语义和 VoiceOver 位置提示。
- 不给人物显示性别、预设姓名或家庭角色。
- 人物选择与身份标签分开完成。

## 5. Shape, Material and Elevation

### 5.1 圆角层级

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `DSRadius.hero` | 22 pt | 页面唯一主卡 |
| `DSRadius.card` | 16 pt | 普通卡片和分组容器 |
| `DSRadius.control` | 14 pt | 按钮、输入框、家务卡片 |
| `DSRadius.glass` | 12-14 pt | 浮动玻璃控件 |
| `DSRadius.pill` | 999 pt | Badge、头像、短筛选器 |

统一使用 continuous corners。分组容器中的连续列表行不再单独设置圆角。

### 5.2 描边层级

| 场景 | 规格 |
| --- | --- |
| 人物和家务插画 | 2.5-3 pt 等效深色轮廓 |
| 主卡与关键按钮 | 1.5 pt，`ink` 约 75% |
| 普通卡片和输入框 | 1 pt，深灰约 18% |
| 玻璃控件 | 0.5-1 pt 白色高光 + 极浅内边界 |
| 分组列表 | 外层统一边界 + 行间分隔线 |

粗黑描边只保留在登录插画、极少量品牌贴纸和关键主操作，不作为所有内容卡片的默认样式。

### 5.3 阴影层级

| Level | 参数 | 用途 |
| --- | --- | --- |
| `flat` | 无阴影 | 动态行、设置行、排行榜行 |
| `raised` | `x:0, y:4, blur:12, black 6-8%` | 普通卡、头像、邀请码 |
| `hero` | `x:0, y:8, blur:24, black 10-12%` | 页面唯一主卡、主要控制 |
| `glass` | `x:0, y:4, blur:16, black 8%` | 底部导航和浮动工具 |
| `pressed` | `x:0, y:2, blur:6, black 6%` | 按压反馈 |

规则：

- 一个页面最多出现 2 个明显悬浮元素。
- 主卡和交互控件可以悬浮，长列表保持平面。
- 登录页可以保留少量 3-4 pt 偏移的品牌硬阴影；功能页不使用密集硬阴影。
- 按压时缩放到约 0.985，并减弱阴影，不做大幅位移。

### 5.4 玻璃材质边界

玻璃只用于：

- 系统底部 Tab Bar。
- 月份、设置、排序等浮动工具按钮。
- DurationPicker 等系统 Sheet。
- 少量悬浮提示。

禁止：

- 把正文和长列表放进大面积玻璃卡。
- 使用紫蓝科技渐变玻璃。
- 在玻璃层上叠加粗黑描边和硬阴影。
- 让透明度影响文字可读性。

开启“降低透明度”时，玻璃回退为不透明 `surfacePure` 或 `canvas`。

### 5.5 间距与稳定尺寸

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `DSSpacing.page` | 20 pt | 页面水平边距 |
| `DSSpacing.section` | 24 pt | 大区块间距 |
| `DSSpacing.cardPadding` | 16-18 pt | 卡片内边距 |
| `DSSpacing.component` | 14 pt | 组件间距 |
| `DSSpacing.list` | 10-12 pt | 列表项间距 |
| `DSControl.minimumTap` | 44 pt | 最小触控区域 |
| `DSControl.buttonHeight` | 52-56 pt | 主要按钮高度 |

## 6. Motion System

### 6.1 原则

只做反馈性动效，不做持续动画。动效应短、轻、跟手、低弹跳，并且不承担唯一的信息表达。

### 6.2 允许的动效

- Tab 切换：系统玻璃选中底座移动，约 0.25 s。
- 卡片按压：缩放到 0.985，阴影减弱。
- 点赞：图标一次轻微脉冲和填充变化。
- 积分刷新：系统 content transition。
- 新动态：轻微淡入和短距离上移。
- Sheet：系统原生出现与消失。
- 记录成功：一次 success haptic，随后返回本周战况。

### 6.3 禁止的动效

- 人物、背景、贴纸持续漂浮或抖动。
- 循环播放的庆祝动画。
- 大幅弹簧、旋转卡片、视差背景。
- 依赖动效才能理解的状态变化。

Reduce Motion 开启时，缩放和位移改为 0.15-0.20 s 淡入淡出，所有状态仍保留文字和图标说明。

## 7. Navigation System

### 7.1 底部导航

底部导航使用系统玻璃材质，四项等宽且始终显示中文标签。

| Tab | 未选中 | 选中 |
| --- | --- | --- |
| 本周战况 | `sun.max` | `sun.max.fill` |
| 记一下 | `plus.circle` | `plus.circle.fill` |
| 月度战报 | `trophy` | `trophy.fill` |
| 我的 | `person.crop.circle` | `person.crop.circle.fill` |

统一规则：

- SF Symbols 约 22 pt、Medium 字重。
- 未选中使用深灰，选中使用统一信息蓝。
- “记一下”不做凸起巨型中间按钮。
- 不混用 Emoji、自绘图标或不同风格的导航图标。
- 不给 Tab Bar 添加粗黑外框或硬阴影。

### 7.2 功能图标

- 设置、点赞、删除、锁定、审核和复制等功能操作统一使用 SF Symbols。
- 家务内容图标 MVP 可使用 SF Symbols；后续统一替换为定制扁平手绘图标。
- 不混用 Emoji、SF Symbols 和来源不一致的插画。
- 自定义家务图标保持 2-2.5 pt 深色线条、少量平涂色和透明背景。

## 8. Component System

### 8.1 通用契约

所有组件必须支持：

- Dynamic Type 和辅助功能字号。
- VoiceOver label、value、hint 与正确 traits。
- 至少 44×44 pt 的可点击区域。
- 不只依赖颜色的状态表达。
- Loading 期间防止重复触发。
- 内容变化时不引起非必要布局跳动。

### 8.2 DSButton

状态：`normal`、`pressed`、`disabled`、`loading`。

- Primary 使用品牌亮黄；Success 使用薄荷绿；Danger 使用珊瑚红；Quiet 使用透明或白色面。
- 标准高度 52-56 pt，圆角 14 pt，关键按钮描边 1.5 pt。
- Loading 保留原尺寸并禁用重复点击。
- Disabled 移除阴影，降低对比，并提供无障碍状态说明。
- Pressed 缩放至约 0.985，阴影切换为 `pressed`。

### 8.3 DSCard / DSScoreCard

- 主卡圆角 22 pt，普通卡 16 pt。
- 页面只保留一张 Hero Card。
- 家庭总积分是今日页主卡核心；家庭成员以重叠头像表示，不放全身人物。
- DSScoreCard 使用等宽数字，并明确“今日”或“本月”的时间范围。
- 禁止完整卡片嵌套完整卡片。

### 8.4 DSChoreCard

- 家庭常用家务采用两列网格；大字号时允许切换单列。
- 卡片显示统一风格图标、家务名、标准时长和积分；名称尽量控制在 5 个字内并保持统一基线。
- 系统家务全部免费，不显示高级锁定遮罩；premium 只影响常用数量上限和自定义位置额度。
- 点击家务打开耗时 Sheet，不直接创建记录。
- 长按后的排序、置顶状态必须为文本和图标保留独立区域，不能与标题重叠。

### 8.5 DSActivityRow

- 左侧 44-48 pt 成员头像。
- 中部第一行显示身份/昵称与家务名称；第二行显示实际耗时和时间。
- 右侧显示积分、`hand.thumbsup` / `hand.thumbsup.fill` 和数量。
- 点赞人头像最多展示 3 个，更多显示 `+N`。
- 动态行位于统一分组容器内，不使用单独粗描边和悬浮阴影。
- `canDelete = true` 时支持左滑删除，但禁止一滑到底直接删除。

### 8.6 DSAvatar

| Size | 数值 | 场景 |
| --- | ---: | --- |
| `compact` | 24 pt | 点赞头像组 |
| `row` | 44-48 pt | 动态与排行榜 |
| `profile` | 72-80 pt | 横向身份主卡 |

- 头像由固定全身立绘裁切。
- 无素材时使用人物固定色和极简轮廓占位。
- 头像提供可访问名称，不只朗读“图片”。

### 8.7 DSRankingRow

- 使用纵向平面列表，不采用占空间的三人领奖台。
- 前三名显示金、银、铜名次标记；其他名次保持中性。
- 每行显示头像、昵称、家庭身份、积分和完成次数。
- 当前用户使用浅色背景和“我”标签，不只依赖颜色。
- 同分显示并列名次。

### 8.8 DSBanner / Empty / Loading

- Loading 使用系统 `ProgressView` 和短文案，不使用闪烁骨架或循环插画。
- Error 使用浅珊瑚 Banner、原因和“重试”。
- 局部失败只影响对应模块。
- 空状态使用静态人物裁切、一句幽默文案和一个明确操作。
- 无网络时保留已有数据，并显示轻量离线提示。

## 9. Page Principles

### 9.1 Login

- 唯一允许完整家务大战插画和漫画品牌标题的页面。
- 标题、插画、三个登录按钮、协议形成清楚纵向结构。
- 手机号为亮黄主按钮；未接入的微信和 Apple 显示“即将支持”或禁用状态。
- 小屏优先缩小插画，不压缩按钮和协议触控区域。

### 9.2 本周战况

顺序固定：

1. 系统 Large Title“本周战况”。
2. 家庭本周总积分主卡。
3. 我的本周积分、完成次数和家庭排名。
4. “家庭动态”标题及右上角“查看全部”。
5. 最近 5 条动态。

主卡只使用成员头像，不放全身人物。动态按时间倒序，点赞后显示成员小头像。完整动态进入次级“家庭动态”页面。

### 9.3 记一下

- 系统 Large Title“记一下”。
- 常用系统家务与自定义位置使用稳定两列网格，卡片高度和名称基线一致。
- 系统家务全部免费，目录按日常家庭、恋爱陪伴、育儿、宠物四主题组织，不显示高级锁定区。
- 免费版最多配置 6 项常用系统家务并由 OWNER 同步全家；高级版系统家务不限数量且成员可个人定制。自定义额度分别为 2 / 10 个，但常用页每次只展示接下来的 2 个空位。
- OWNER 长按卡片进入排序/置顶状态；滑到页面底部继续上拉，以一次轻触感反馈进入家务库，不保留右上角“编辑常用”。
- 最后一排必须完整滚出 Tab Bar 安全区，上拉触发区不遮挡家务卡片。

### 9.4 ChoreDurationPickerSheet

- 系统半高 Sheet、拖拽指示器和 `.wheel` Picker。
- 顶部只显示家务图标与名称，不显示“系统建议”。
- 中间是分钟滚轮，下面实时显示预计积分。
- 首次使用标准时长；之后读取该家务上次确认耗时。
- 取消不保存，确认后返回本周战况并刷新数据。
- Sheet 使用轻玻璃和轻阴影，不使用爆炸框或粗描边。

### 9.5 月度战报

顺序固定：

1. 系统 Large Title 与无独立阴影的月份切换控件。
2. 本月领先人物主卡，作为页面唯一一级悬浮主卡。
3. 家庭总积分、完成次数、总耗时次级摘要。
4. 一句平面家庭战报总结，不再包成独立卡片。
5. 单个“本月结构”次级容器：上半部为四主题圆环，下半部为家务大类分段比例条与双列图例。
6. 平面成员排行榜，依靠分隔线和名次建立层级，不使用每行独立卡片。

视觉层级固定为三档：领跑者卡为一级；摘要与“本月结构”为二级；战报文案和排行榜为平面三级。除领跑者卡外不得复制同等强度的阴影、彩色底或描边。

月报为实时战报：

- 单人领先显示“本月暂居第一”。
- 多人同分显示“并列领跑”和头像组合。
- 全员零分显示“本月战局待开启”和家庭成员集合，不显示空白页。
- 月底结算后使用“本月家庭冠军”。

月报主卡是功能页中展示全身人物的主要场景。

### 9.6 我的

- 不显示顶部“我的”Large Title。
- 页面直接以横向身份主卡开场：左侧头像，右侧依次显示加粗家庭名称、家庭身份和昵称。
- 不保留无明确行为的设置按钮；OWNER 点击家庭名称进入轻量编辑，MEMBER 保持只读。
- 身份主卡之外使用白色分组列表。
- 家庭组显示邀请码、家庭形象、复制和系统分享；不暴露数据库 familyId。审核加入申请仅 OWNER 显示。
- 家庭成员使用无额外白色外圈的头像列表；昵称下方显示家庭身份，OWNER 以头像角标皇冠表达。
- 点击其他 ACTIVE 成员进入近 30 天动态详情；只有 OWNER 查看另一位 MEMBER 时显示“转让一家之主”。
- Profile 不单独显示“成员状态”行，OWNER / MEMBER 身份由身份主卡、OWNER Badge 和可用工具自然表达。
- Profile 不显示“图片凭证”行或“即将开放”占位；该能力在 MVP 个人页中完全隐藏。
- Debug 仅 Debug 构建显示并默认折叠。
- 未完成入口隐藏，不展示无行为按钮。
- 退出登录位于底部，使用红色文字按钮。

### 9.7 创建与加入家庭

- 创建家庭采用单页三段式：家庭名称 → 人物形象 → 家庭身份。
- 选择“自定义”身份时才显示输入框。
- 图片凭证显示“即将开放”且不可开启。
- 加入家庭使用邀请码，不显示数据库 familyId。
- 申请后展示明确的等待 OWNER 审核状态。

### 9.8 OWNER 审核

- 使用系统紧凑导航标题“加入申请”。
- 申请按时间倒序排列。
- 每行显示头像、昵称、身份和申请时间。
- 通过使用薄荷绿轻按钮；拒绝使用珊瑚红文字按钮。
- 通过不额外确认；拒绝需要系统确认。

## 10. Interaction and Safety

### 10.1 记录成功

- 收起耗时 Sheet。
- 提供一次轻量成功触感。
- 自动切换到本周战况。
- 更新家庭总积分、个人积分和排名。
- 新动态行轻微淡入并上移。

### 10.2 邀请码

- 创建家庭成功后重点展示一次。
- 个人页长期保留。
- 使用等宽字体与适当字符间距。
- 提供复制和系统分享。
- MVP 不制作复杂邀请海报或二维码。

### 10.3 危险操作

- 删除记录：左滑出现删除，禁止 full swipe，点击后系统确认。
- OWNER 删除他人记录时，确认文案显示成员和家务名称。
- 拒绝加入和退出登录需要系统确认。
- 取消点赞、切换月份和取消耗时选择无需确认。
- 所有确认使用系统 `confirmationDialog`，不制作漫画弹窗。

## 11. Responsive and Accessibility

- 主设计基准为 393×852，最低适配到 375 pt 宽。
- 主页面允许纵向滚动，不缩小字号强塞首屏。
- 家务双列卡片名称最多两行；大字号可切换单列。
- 卡片随 Dynamic Type 纵向扩展，不固定内容高度。
- Sheet 在小屏下允许内部滚动，不写死高度。
- 长昵称、家庭名和身份优先换行；次要信息才截断。
- 底部内容始终为玻璃 Tab Bar 与安全区预留空间。
- MVP 以竖屏为主；横屏保证可操作，但不单独设计布局。
- 所有触控区域至少 44×44 pt。
- 排名、点赞、选中和错误不能只靠颜色表达。
- 角色图片提供有意义的辅助功能描述，纯装饰图形不朗读。
- Reduce Motion 取消缩放和位移。
- Reduce Transparency 将玻璃回退为不透明奶油白。

## 12. 原型与 SwiftUI 落地顺序

1. 统一颜色、字体、圆角、描边、阴影、玻璃和动效 Token。
2. 固定底部导航图标和系统 Large Title 规则。
3. 先落地 Today、Record、Duration Sheet、Monthly、Profile 五个核心表面。
4. 再落地 CreateFamily、JoinFamily、JoinRequests、ActivityAll 等次级页面。
5. 最后补全 Loading、Error、Empty、Offline、Dynamic Type 和 Reduce Motion 验收。

每轮验收必须确认：

- 页面仍有约 80% 白色或奶油色空间。
- 功能页没有密集粗黑边框和硬阴影。
- 每页只有一张视觉主卡。
- 四个 Tab 的图标、顺序与标签一致。
- 未完成功能没有伪装成可点击入口。
- 所有文字、按钮和卡片在 375 pt 宽及大字号下不重叠。
