# 统一账号身份体系

更新时间：2026-09-02

## 1. 目标

手机号、Apple 和微信只负责证明“用户是谁”，业务数据继续统一归属于稳定的 `User.id`。
昵称、头像、家庭身份和重新加入家庭均不参与账号匹配，也不会触发账号合并。

## 2. 已冻结规则

- 首发手机号仅支持中国大陆号码，统一为 `+86xxxxxxxxxxx`。
- 一个 `User` 可以同时绑定 `PHONE`、`APPLE` 和 `WECHAT`。
- 同一个外部身份只能属于一个 `User`。
- 同一个 `User` 每种登录方式最多绑定一个身份。
- 不根据昵称、头像或相似手机号自动合并账号。
- 身份冲突时返回冲突错误，用户必须登录原账号后再绑定。
- 解绑后必须至少保留一种可用登录方式。
- 注销账号时身份记录随 `User` 一并删除。
- Apple 使用稳定的 `sub`；微信后续优先使用 `unionid`，否则使用带类型前缀的 `openid`。
- 允许同一账号同时登录多台设备；普通退出只撤销当前设备，“退出所有设备”撤销全部会话。
- Access Token 有效期 15 分钟；Refresh Token 30 天滑动续期，单次会话最长 90 天。
- Refresh Token 每次使用后强制轮换，旧 Token 重放会撤销所属会话。
- 旧版无有效期 Access Token 在本机制上线后一次性失效。

## 3. 数据模型

`AuthIdentity` 仅保存认证映射：

| 字段 | 用途 |
| --- | --- |
| `userId` | 关联稳定的内部用户 |
| `provider` | `PHONE`、`APPLE`、`WECHAT` 或仅开发环境使用的 `DEV` |
| `providerSubject` | 服务商返回的稳定身份标识 |
| `verifiedAt` | 最近一次完成可信验证的时间 |
| `lastUsedAt` | 最近一次通过该身份登录的时间 |

数据库同时约束 `provider + providerSubject` 和 `userId + provider` 唯一。

`AuthSession` 表示一台设备的一次登录，保存设备摘要、最近活跃时间、30 天空闲到期时间、90 天绝对到期时间和撤销原因。
`AuthRefreshToken` 保存该会话历次 Refresh Token 的 SHA-256 哈希、到期时间与是否已使用；Token 原文只返回客户端并保存在 Keychain。

## 4. 旧账号迁移

- 保留原 `User.id`、家庭关系、家务记录、积分、会员状态和成就。
- 可识别的大陆手机号映射为 `PHONE`，身份值转换为 `+86` 格式。
- E2E、内部测试等非手机号标识映射为 `DEV`，正式版不提供该入口。
- `User.phoneNumber` 暂时保留兼容，不作为长期身份主键。
- 迁移前检查归一化冲突；发现两个账号落到同一手机号时直接停止，不自动合并。
- 回滚脚本只删除新身份表和枚举，不改写旧 `User.phoneNumber`，因此不会丢失旧登录信息。

## 5. 服务边界

当前阶段已经提供统一身份解析、创建、登录接管、绑定、解绑和冲突处理服务。
真实短信、Apple、微信接口必须先完成各自凭证验证，再调用身份服务；不提供允许客户端直接提交任意
`providerSubject` 的公共绑定接口。

## 6. 后续接入顺序

1. 接入短信验证码，并在验证成功后登录或绑定 `PHONE`，复用现有会话签发服务。
2. 接入 Sign in with Apple，服务端验签后登录或绑定 `APPLE`。
3. 接入微信授权，服务端换票后登录或绑定 `WECHAT`。
4. 增加账号安全页中的绑定状态、解绑与冲突引导。
5. 稳定运行一个版本后移除 `User.phoneNumber` 的身份主键职责。

## 7. 验收重点

- 同一手机号不同格式返回同一个 `User.id`。
- 同一用户使用已绑定的不同方式登录，始终返回同一个 `User.id`。
- 相同 Apple/微信身份不能绑定到两个用户。
- 解绑最后一种登录方式必须失败。
- 昵称相同的两个用户不会被合并。
- 注销后身份记录、会话和个人数据按注销规则删除。
- 两台设备可以同时使用，退出当前设备不影响另一台设备。
- Refresh Token 轮换后旧 Token 不能再次使用；重放时整条会话立即失效。
- iOS 在 Access Token 剩余 1–2 分钟时合并并发请求并静默刷新。
