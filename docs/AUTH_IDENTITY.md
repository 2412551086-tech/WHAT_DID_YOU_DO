# 统一账号身份与首次使用流程

更新时间：2026-09-03

## 1. 产品原则

- 先使用，后注册；只有创建正式家庭、加入已有家庭、邀请成员或开启云同步时才要求认证。
- 第一次打开 App 直接选择“创建新家庭”或“加入已有家庭”，不展示登录页。
- 创建路径先建立 `LocalDraftFamily`，最多启用 6 项家务，并允许离线记录；数据至少跨 App 重启保存。
- 加入路径先输入邀请码并查看公开家庭预览，确认加入时再出现认证门槛。
- 认证成功后认领当前本地草稿，不重新配置家庭或家务，也不重复导入记录。

## 2. 已冻结的 Provider 规则

| 发行区域 | 正式登录方式 |
| --- | --- |
| `CN` | `APPLE`、`WECHAT`、`EMAIL` |
| `GLOBAL` | `APPLE`、`GOOGLE`、`EMAIL` |

- 区域由发行配置显式指定，不根据 IP 自动判断。
- `EMAIL` 第一版使用一次性验证码，不建立密码体系。
- `DEV` 只用于 Debug 与自动化测试，Release 不显示。
- 一个 `User.id` 可以绑定多种身份，但同一用户每种 Provider 最多绑定一个身份。
- Provider 返回的稳定标识是身份依据；昵称、头像和家庭身份都不是。
- 两个已经存在的 `User.id` 不自动合并；身份冲突必须显式报错。

## 3. 数据模型

`AuthIdentity` 保存外部身份到稳定内部用户的映射：

| 字段 | 用途 |
| --- | --- |
| `userId` | 稳定内部用户 |
| `provider` | `APPLE`、`WECHAT`、`EMAIL`、`GOOGLE` 或开发专用 `DEV` |
| `providerSubject` | 服务商验证后返回的稳定标识 |
| `verifiedAt` | 完成可信验证的时间 |
| `lastUsedAt` | 最近一次使用时间 |

数据库约束 `provider + providerSubject` 和 `userId + provider` 唯一。邮箱标识统一转为小写；Apple 使用 `sub`；微信优先使用 `unionid`，否则使用带类型前缀的 `openid`；Google 使用 `sub`。

`AuthSession` 表示一台设备的一次登录。Access Token 有效期 15 分钟；Refresh Token 采用 Rotation，30 天滑动续期，单次会话最长 90 天。旧 Refresh Token 重放会撤销所属会话。iOS 将 Token 对存入 Keychain，并在 Access Token 剩余约 2 分钟时静默刷新。

## 4. 本地草稿认领

`LocalDraftFamily` 保存草稿 ID、创建时间、家庭名、最多 6 项家务、本地记录和认领状态。iOS 使用受保护的 JSON 文件原子写入 Application Support。

认证后调用 `POST /families/claim-local-draft`：

1. 服务端按 `draftId` 幂等认领，同一草稿不会创建两个家庭。
2. 服务端验证系统家务的稳定 `catalogKey`，自定义家务最多 2 项。
3. 服务端重新计算积分，不信任客户端上传的积分或倍率。
4. 记录时间必须位于本地体验窗口内。
5. 家庭、OWNER 成员、家务布局、记录、成就事件和认领凭据在同一事务中创建。
6. 成功后客户端删除本地草稿；失败时保留并允许重试。

## 5. 加入家庭的延迟认证

未登录用户通过公开的 `GET /family-invitations/:inviteCode` 读取经过裁剪的家庭预览。只有点击确认加入后才进入认证页；认证成功后使用原邀请码提交加入申请。公开预览不返回当前用户状态或任何联系方式。

## 6. 删除与历史迁移

- 账号注销会撤销全部会话，并按现有注销规则删除相关身份和个人数据。
- 已经执行过的历史迁移不改写、不删除；通过新的前向迁移移除废弃表、字段和枚举值。
- 原有业务 `User.id`、家庭关系、家务记录、积分、会员状态和成就保持不变。

## 7. 后续真实接入

1. Apple：客户端原生授权、nonce、防重放、服务端验签和注销时撤销授权。
2. 微信：移动应用审核、Universal Link、客户端授权、服务端换票和稳定标识映射。
3. 邮箱：选择邮件服务商，完成验证码发送、摘要保存、频控、过期和单次消费。
4. Google：仅海外发行启用，完成客户端授权和服务端 ID Token 验签。
5. 账号安全页：展示绑定状态、解绑保护和身份冲突引导。

## 8. 验收重点

- 首次启动没有登录页，本地选择与记录跨重启保留。
- 本地草稿重复认领只产生一个家庭和一份记录。
- 输入邀请码不要求登录，确认加入才要求认证。
- 国内与海外构建只显示各自三个正式 Provider。
- 同一外部身份始终返回同一个 `User.id`，冲突时不自动合并。
- 多设备登录、当前设备退出、全部设备退出、Rotation 和重放撤销保持有效。
