先打开 Docker Desktop，然后检查容器：

```sh

```

如果数据库容器已经创建但未运行：

```sh

```

如果尚未创建：

```sh
docker run --name ni-gan-sha-la-postgres \
  -e POSTGRES_USER=app \
  -e POSTGRES_PASSWORD=app123456 \
  -e POSTGRES_DB=ni_gan_sha_la \
  -p 5432:5432 \
  -d postgres:16
```

## 2. 本地启动 iOS

1. 用 Xcode 打开 `/Users/aoxideni/Documents/what_did_you_do/apps/ios/WhatDidYouDo.xcodeproj`。
2. 顶部 Scheme 选择 `WhatDidYouDo`。
3. 选择已安装的 iPhone Simulator。
4. 确认 `APIConfig.useMockData = false`，用于 API 联调。
5. 模拟器 Debug 默认使用 `localSimulator`，访问 `http://127.0.0.1:3000`。
6. 确认后端仍在 `http://127.0.0.1:3000` 运行。
7. 按 `Command + R` 启动 App。

### 2.1 API 环境切换

iOS 当前支持三种 API 环境：

- `localSimulator`：模拟器联调，默认 `http://127.0.0.1:3000`。
- `localNetwork`：真机或其他设备联调，使用 Mac 的局域网 IP，例如 `http://192.168.1.10:3000`。
- `production`：Release/Production 预留 HTTPS 地址。

Debug 模式默认 `localSimulator`。在 Xcode 中临时切换：

1. 点击顶部 scheme `WhatDidYouDo`。
2. 选择 `Edit Scheme...`。
3. 进入 `Run > Arguments > Environment Variables`。
4. 添加：

```text
WDD_API_ENV=localNetwork
WDD_LOCAL_NETWORK_BASE_URL=http://你的Mac局域网IP:3000
```

如果要回到模拟器本机后端，删除这两个环境变量，或设置：

```text
WDD_API_ENV=localSimulator
```

Release 构建不会使用 `localSimulator`，避免把 `127.0.0.1` 带进发布包。

运行 iOS 单元测试：

- Xcode：按 `Command + U`。
- 命令行：

```sh
xcodebuild test \
  -project /Users/aoxideni/Documents/what_did_you_do/apps/ios/WhatDidYouDo.xcodeproj \
  -scheme WhatDidYouDo \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5'
```

如果模拟器名称或系统版本不同，先运行：

```sh
xcrun simctl list devices available
```

## 3. 双账号主链路手测

建议每轮使用两个新的测试手机号，例如时间戳后缀，避免旧家庭状态干扰。

### 用户 A 创建家庭

1. 输入手机号 `123456` 和任意开发验证码，点击手机号登录；确认登录页不要求昵称。
2. 在创建家庭页填写或修改昵称，再选择身份和头像占位。
3. 确认图片凭证入口不可开启，创建请求保持 `requirePhotoProof=false`。
4. 进入“我的”，复制家庭邀请码。
5. 确认当前成员身份为 OWNER/一家之主。

### 用户 B 申请加入

1. 用户 A 退出登录。
2. 输入手机号 `654321` 登录。
3. 选择加入家庭，粘贴邀请码，不输入数据库 familyId。
4. 选择身份和头像，提交申请。
5. 确认页面提示等待一家之主审核。
6. 审核前确认用户 B 不能进入家庭记录家务。

## 4. OWNER 审核

1. 用户 B 退出登录，重新用 `123456` 登录。
2. 进入“我的”或家庭设置中的审核入口。
3. 确认列表显示用户 B 的昵称、身份和头像。
4. 点击通过。
5. 再次使用 `654321` 登录。
6. 确认用户 B 可以看到家庭并创建家务记录。
7. 另建一条申请验证拒绝后，申请人不能读取家庭数据。

## 5. 家务与实际耗时

1. 用户 B 点击“记一下”。
2. 点击一个未锁定家务，确认不会立即创建记录。
3. 确认滚轮首次使用家务标准时长。
4. 修改耗时并确认记录。
5. 回到首页，确认本周积分和本周记录立即更新。
6. 再次点击同一家务，确认默认值为上次确认耗时。
7. 修改滚轮后点取消，再次打开，确认取消值没有保存。
8. 点击另一家务，确认耗时记忆互不影响。
9. 免费家庭确认积分倍率只读，预计积分仍按系统倍率随耗时变化。
10. 点击“高级版可自定义倍率”，确认权益对比页包含“积分倍率：系统固定 / 0.5–2.0x”。
11. 兑换高级版后把倍率调到 2.0x，选择 20 分钟并记录，确认预计与实际入账均为 40 分。

### 自定义家务

1. 在自定义区创建第一个家庭共享家务，选择 10 个自定义图标之一。
2. 确认名称最多输入 5 个字；修改名称、标准时长和 0.5x...2.0x 积分倍率后，其他 ACTIVE 成员也能看到。
3. 创建第二个自定义家务后，确认免费家庭不能再新增第三个有效模板。
4. 输入开发兑换码 `241255`，确认额度扩展到 10 项；创建第 11 项时应被拦截。
5. 高级版尚未创建自定义家务时，常用页只显示 2 个空白自定义位置；每创建一项后仍只追加接下来的 2 个空位。
6. 编辑模板后确认历史记录不被重写；归档后确认模板不再出现在选择列表。

### 常用家务与系统目录

1. 新建家庭后，确认 OWNER 先进入常用家务设置，而不是直接进入首页。
2. 确认家务库按“日常家庭、恋爱陪伴、育儿、宠物”四主题展示全部 36 项免费系统家务。
3. 免费账号分别保存 1 项和 6 项常用家务；确认两种数量都合法，选择第 7 项时弹出高级版权益页。高级测试账号确认系统家务数量不受该上限限制。
4. 免费 OWNER 调整常用家务后，用普通成员登录确认读取相同布局且不能排序或进入家务库修改。
5. 普通成员兑换高级版后保存个人布局，再切回 OWNER，确认两人的常用家务互不覆盖。
6. 免费用户点击新增自定义家务时确认展示权益页；OWNER 在尚有 2 个免费名额时可以选择“先使用免费额度”，普通成员没有该继续入口。
7. 设置置顶并长按调整顺序，保存后确认“记一下”只展示已选项与自定义位置，且置顶项优先。
8. 在“记一下”滑到最底部后继续上拉，确认触感反馈后进入家务库；不应依赖右上角“编辑常用”按钮。
9. 免费 OWNER 在家务库替换一项，确认其他家庭成员读取到相同配置。
10. 确认全部系统家务都能直接打开耗时选择器，不显示高级锁定遮罩。
11. 在常用卡片区域上下滑动，确认不会误触记录或布局；轻触卡片进入耗时选择，长按约 0.8 秒后才进入布局。
12. 布局模式下拖动排序或移除后松手，确认自动保存并退出；切换 Tab、打开弹窗或离开页面也应退出布局状态。
13. 高级 MEMBER 关闭“沿用一家之主布局”并保存个人布局，确认 OWNER 的后续改动不会覆盖；重新打开后确认恢复家庭共享布局。

## 6. 点赞、表情回应与取消

1. 使用用户 A 查看用户 B 的记录。
2. 点击点赞，确认图标、likeCount 和点赞头像更新。
3. 首次普通点赞后确认只出现一次“长按可以选回应”提示。
4. 长按回应按钮，确认出现点赞、击掌、黑脸、笑哭、调侃五种回应。
5. 依次切换两个不同回应，确认 likeCount 不重复增加，头像角标和当前按钮同步变化。
6. 点击已回应按钮，确认取消回应且计数更新。
7. 重复 POST 回应和重复 DELETE 取消，确认接口幂等且页面不报冲突。
8. 使用 VoiceOver 聚焦按钮，确认能听到长按提示，并可通过“选择回应”辅助操作打开选择框。

## 7. 左滑软删除

1. 用户 B 左滑自己创建的记录，确认显示删除按钮。
2. 用户 B 查看用户 A 的记录，确认不能删除。
3. 用户 A 作为 OWNER，确认可以删除用户 B 的记录。
4. 删除后确认记录从今日动态和最近动态消失。
5. 重新启动 App，确认记录不会重新出现。

## 8. 本周、最近、排行和月报

1. 连续创建两条记录，确认本周积分等于家庭时区本周内记录 points 之和。
2. 本周战况使用 `activity?range=week`，范围为家庭时区周一 00:00 到下周一 00:00。
3. 家庭最近动态使用 `activity?range=recent`，最多展示后端最近 30 条。
4. 删除一条记录后，确认本周积分和记录数立即减少。
5. 确认月排行榜的积分和记录数同步减少。
6. 在月度战报切换上月、上上月和当前月，确认不能进入未来月份。
7. 确认各月份 totalPoints、totalRecords、recentRecords 和排行随月份变化。
8. 确认月报主视觉使用所选月份积分第一名成员的配套立绘；无数据时使用回退立绘。
9. 确认主题圆环只统计所选月份记录，四主题占比、积分和次数与 `themeStats` 一致；零记录月份不绘制错误圆环。
10. 确认家务大类分段条与图例合计一致，数据来自 `categoryStats`，没有重复堆叠多组抢焦点进度条。
11. 确认页面只有领跑者卡为一级悬浮主卡；摘要与“本月结构”为次级，成员排行为平面列表。
12. 点击家庭本周总积分卡，确认家庭周分析的每日趋势、成员贡献、类别结构和本周动态都随所选周变化。
13. 点击个人积分/次数/排名区域，确认个人周分析只统计本人，并展示个人趋势、常做家务、平均耗时和本周记录。
14. 确认本周动态时间按家庭时区显示为“周几 HH:mm”，切换历史周后仍显示正确。

## 12. 常见问题排查

### 3000 端口被占用

```sh
lsof -i :3000
kill <PID>
```

优先正常 `kill`，进程无法退出时再使用 `kill -9 <PID>`。

### 浏览器访问 `/` 返回 404

这是正常现象，后端没有根路由。使用下面的地址验证家务接口：

```sh
curl -i http://127.0.0.1:3000/chores
```

### inviteCode 无效

- 使用家庭页面显示的 8 位邀请码，不要使用 `cm...` 形式的数据库 familyId。
- 检查是否复制了空格；后端会自动 trim 并转为大写。
- 确认该邀请码来自当前数据库中的家庭。

### token 丢失或返回 401

- accessToken 已使用 Keychain 持久化；退出登录会清除 token。
- 如果 token 过期或后端返回 401，App 会清除本地登录态并回到登录页。
- 退出登录后 token 会被清除。
- 检查 DebugPanel 的 token 状态、最后请求和状态码。

### iOS 仍处于 Mock 模式

打开 `apps/ios/Sources/Core/Network/APIConfig.swift`，确认：

```swift
static let useMockData = false
```

修改后停止 App，再按 `Command + R` 重新运行。

### 真机不能访问 `127.0.0.1`

真机中的 `127.0.0.1` 指向 iPhone 自己。请切换到 `localNetwork`，并把 `WDD_LOCAL_NETWORK_BASE_URL` 配成 Mac 的局域网 IP，例如：

```text
http://192.168.1.10:3000
```

Mac 与 iPhone 必须在同一局域网，并允许防火墙放行 Node/Nest 服务。
