## P0：家务创建幂等

- [x] **iOS 创建家务时发送 `Idempotency-Key`**
  - 当前状态：iOS 与后端均已接入。
  - 用户每次点击“确认记录”时生成一个 UUID。
  - 同一次请求的网络重试必须复用同一个 UUID。
  - 下一次新建家务记录时生成新的 UUID。
  - 不得在每次重试时重新生成 UUID。
  - 验收：相同 Key 连续提交两次，只产生一条家务记录、一份积分和一次成就事件。

- [x] **为 iOS 幂等请求补充自动化测试**
  - 验证同一次重试复用 Key。
  - 验证下一次记录使用新 Key。
  - 验证相同 Key 配合不同请求内容时正确处理 `409`。

## P1：统一账号身份体系

- [x] **新增统一 `AuthIdentity` 数据模型**
  - 建议字段：`id`、`userId`、`provider`、`providerSubject`、`createdAt`。
  - `provider` 至少支持 `PHONE`、`APPLE`、`WECHAT`。
  - 建立 `provider + providerSubject` 唯一约束。
  - 所有登录方式最终都映射到稳定的内部 `User.id`。
  - 不使用昵称匹配或合并账号。

- [x] **迁移现有开发手机号用户**
  - 将现有 `User.phoneNumber` 转换或同步为 `PHONE` 身份记录。
  - 保留原 `User.id`，避免家庭关系、家务记录和成就归属丢失。
  - 提供可回滚 migration 和重复执行保护。

- [x] **实现账号绑定与冲突处理核心服务**
  - 已登录用户可以绑定手机号、Apple 或微信身份。
  - 新身份已被其他用户占用时，不得静默合并。
  - 合并账号必须经过重新验证和明确确认。
  - 退出家庭、重新加入、改昵称均不能改变身份归属。

## P1：正式登录

- [ ] **接入正式短信验证码登录**
  - 接入短信服务商，增加发送、校验、频率限制和验证码过期时间。
  - 手机号按统一格式保存，不能继续使用当前不校验长度的开发登录规则。
  - 当前 `POST /auth/mock-login` 仅保留在开发环境。

- [ ] **接入 Apple 登录**
  - iOS 使用 Sign in with Apple。
  - 后端验证 Apple identity token、签名、audience、issuer、过期时间和 nonce。
  - 使用 Apple 稳定 `sub` 作为 `providerSubject`。

- [ ] **接入微信登录**
  - 完成微信开放平台应用配置和 iOS SDK 接入。
  - 后端使用授权 code 换取并验证身份。
  - 优先使用 `unionid`；不可用时使用当前应用范围的 `openid`。

## P1：正式会话安全

- [x] **升级 access token 与 refresh token 体系**
  - access token 设置较短有效期。
  - refresh token 支持轮换、撤销、设备退出和泄漏失效。
  - iOS 继续使用 Keychain 保存敏感 Token。
  - Token 和完整认证凭据不得写入日志或 UserDefaults。

- [x] **增加认证安全与回归测试**
  - 覆盖过期 Token、错误签名、被撤销 Token 和 refresh token 重放。
  - 覆盖同一用户使用不同已绑定方式登录后返回同一个 `User.id`。
  - 覆盖未绑定的不同登录方式不会按昵称自动合并。

## 推荐实施顺序

1. iOS 家务创建接入 `Idempotency-Key`。
2. 新增 `AuthIdentity` 与现有手机号身份迁移。
3. 实现账号绑定和冲突处理。
4. 接入正式短信验证码。
5. 接入 Apple 登录。
6. 接入微信登录。
7. 升级 access token/refresh token 和会话撤销机制。
8. 完成安全测试、双账号回归和生产配置隔离。
