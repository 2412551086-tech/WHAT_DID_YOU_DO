更新时间：2026-08-13

## 1. 文档定位

本计划把 [家庭家务成就系统完整开发文档](./家庭家务成就系统完整开发文档.md) 转换为适合当前仓库执行的工程阶段、交付物和验收门槛。

## 2. 当前项目基础

已经具备：

- NestJS + Prisma + PostgreSQL 后端，以及 migration、seed、Jest、e2e 和 smoke test。
- SwiftUI + MVVM、Mock/API 切换、Keychain、环境配置和 XCTest。
- 家庭 `timezone`，可用于家庭本地日、周和月份范围。
- 稳定 `userId + familyId` 成员关系，退出后使用 `LEFT` 保留历史。
- 家务记录软删除、实际耗时、标准主题/大类、回应和创建者快照。
- 免费/高级版常用家务与自定义家务容量规则。
- 成就定义、事件、进度、解锁、奖励、审计和资格快照数据模型，以及 59 条幂等 V1 定义。
- 服务端 `occurredAt`、禁止补记、10 秒删除撤销和家务创建请求幂等键。
- 事务 Outbox、同仓库数据库 worker、处理租约、指数退避、死信查看/重放和同步状态 API。

本地工程已经具备：

- ACTIVE 成员周期资格快照、家庭时区规则和个人/家庭/搭档归属。
- 成长、专长、互动、家庭协作、搭档、长期里程碑和隐藏彩蛋规则。
- 统一 iOS 成就网格、详情、成员级家庭可见总开关、本地缓存、最多 3 个近期目标和中央横向解锁反馈。
- DIRTY 对账修复、死信/积压健康检查、人工重放、档案与生命周期归档。
- 27 枚正式成就资源的 Asset Catalog 接入和关联成就复用映射。

仍需发布环境完成：完整 47 枚独立视觉、外部告警、数据库备份/恢复演练、事件重放/全量对账演练和 TestFlight 家庭灰度。

## 3. 开发前必须冻结的决策

以下决策已于 2026-08-10 冻结，后续实现必须使用同一口径：

| 决策 |




| 当前实现差距 |
| ---- | ---- | ---- |
| 高级版自定义家务上限 | 产品显示“不限”；每家庭最多 100 个未归档项目作为服务端内部保护 | 后端与 iOS 容量口径已统一为 100 |
| 业务发生时间 | V1 不允许补记；`occurredAt` 由服务端创建记录时生成，旧数据以 `createdAt` 回填 | 已完成 |
| 参与角色 | 不新增 `PARTICIPANT/OBSERVER`；全部 ACTIVE 成员参与适用的家庭成就 | 复用现有 status 即可 |
| 删除恢复 | 删除后提供 10 秒“撤销”，不做回收站，超时后不允许用户恢复 | 已完成 |
| 通知 | V1 暂不做；登记到后续统一通知系统，届时一并设计应用内通知和 Push | 当前无正式通知系统 |
| 家庭排行榜 | 保留现有积分排行榜；成就系统不新增排名型、输赢型或差距型成就 | 无需移除现有排行榜 |
| 规则执行方式 | 家务立即成功；数据库 Outbox + 同仓库 worker 异步结算成就，首版不引入 Redis | 阶段 2 已完成事件管道；阶段 3 接入规则结算 |

任何变更都必须先更新完整说明书、规则版本和验收用例，不能在代码中悄悄形成第二套口径。

## 4. 总体拆分

建议分为 8 个阶段。每一阶段单独提交、单独迁移、单独验收，不把整个系统塞进一个超大 PR。

```text
0. 规则冻结与数据字典
1. 数据模型与兼容迁移
2. 事件管道与幂等处理器
3. 个人成长与家庭权益纵向闭环
4. iOS 成就基础体验
5. 家务专长与防刷
6. 家庭互动、协作与搭档
7. 长期里程碑、彩蛋与上线保障
```

## 7. 阶段 2：事件管道与幂等处理器

> 状态：已完成（2026-08-11）。migration：`20260811140000_add_chore_record_idempotency`。事件管道可灰度启用，尚未执行成就规则或发放奖励。

### 目标

让成就失败不阻塞家务主流程，并且事件可重试、可审计、可重放。

### 工作内容

- 家务创建/删除/10 秒撤销、回应、成员加入/退出和套餐变化同事务写入 Outbox。
- 实现数据库轮询 worker、事件认领、超时释放、指数退避和失败状态。
- 实现规则注册表、受影响规则筛选和幂等消费骨架。
- 实现 `PENDING | PROCESSING | SUCCEEDED | FAILED` 状态和查询接口。
- 建立死信查看、人工重放和基础审计命令。
- 核心接口立即返回业务成功和成就 `PENDING`；不得等待成就计算或要求重记家务。

### 验收

- 同一业务请求重试 10 次，只产生 1 个业务结果和 1 个有效事件。
- 同一事件消费 10 次只更新一次进度。
- worker 停止时家务仍可创建；恢复后可自动补算。
- 唯一冲突被视为已处理，不返回 500。
- 失败事件保留错误码、重试次数和可重放信息。

## 8. 阶段 3：个人成长与家庭权益纵向闭环

> 状态：已完成（2026-08-11）。当前由 `ACHIEVEMENTS_ENABLED` 灰度控制；iOS 成就体验已在阶段 4 完成。

### 目标

先完成最有留存价值的一条端到端闭环，再扩展完整目录。

### 首批范围

- `FIRST_RECORD`
- `ACTIVE_DAYS_3`
- `ACTIVE_DAYS_5`
- `ACTIVE_DAYS_7`
- `STREAK_7`
- `STREAK_14`
- `HABIT_30`

### 工作内容

- 实现家庭时区下的个人活跃日、严格连续和滚动 25/30 计算。
- 实现 MemberAchievement、Progress、UnlockBatch 和 FamilyRewardGrant 原子写入。
- 容量计算从固定数字改为“套餐基础 + 永久成就奖励”。
- 同一成员可获得个人徽章，同一家庭只获得一次相同容量奖励。
- 删除只回退尚未解锁的真实进度，不撤销已解锁荣誉和奖励。
- 提供 summary/me/detail/visibility API 和创建家务的 evaluation 响应。

### 验收

- 3/5/7 使用累计活跃日，不要求连续；7/14 使用严格连续。
- 同一天多条记录只增加 1 个活跃日。
- A、B 都能获得个人成就，但家庭容量只增加一次。
- 并发触发不会重复解锁或重复扩容。
- 成员退出不带走家庭奖励；进入新家庭后按新关系重新计算。
- 删除触发记录后，已发奖励不回收，未解锁进度可正确重建。
- 免费版容量在接口、iOS限制和高级版营销页中一致。

### 实际交付

- 按记录创建时的 `familyTimezoneSnapshot` 计算不可变家庭本地业务日，旧记录缺少事件时回退到当前家庭时区。
- 已实现 `FIRST_RECORD`、累计活跃 3/5/7 日、严格连续 7/14 日和滚动 30 日活跃 25 日。
- worker 在同一事务内写入 Progress、UnlockBatch、MemberAchievement、FamilyRewardGrant、审计日志和事件成功状态。
- 家庭级 PostgreSQL advisory lock 与唯一索引共同保证并发下个人解锁和家庭权益不重复。
- 删除后重算真实进度；已解锁的展示值、徽章和永久家庭奖励不回收。
- 免费家庭常用家务容量改为 `6 + COMMON_CHORE_SLOT`，自定义家务容量改为 `2 + CUSTOM_CHORE_SLOT`；高级版自定义家务内部保护上限为 100。
- 已提供 summary、me、detail、visibility 与带解锁批次的 sync API。

## 10. 阶段 5：家务专长与防刷

### 目标

上线次数、时长和类别覆盖三类个人专长，并保证可信度。

### 工作内容

- 实现洗碗、烹饪、垃圾、宠物、育儿、地面、洗护、恋爱、收纳和六边形专长。
- 支持铜、银、金独立解锁和跨级批次聚合。
- 同成员、同标准子类、同自然日最多计入 3 次。
- 未启用主题不展示、不推荐、不计算。
- 自定义家务只根据标准映射统计，不解析用户标题关键词。
- 实现时长异常范围，以及拒绝客户端传入 `occurredAt` 的校验。

### 验收

- 同子类第 4 条记录仍是有效家务，但不增加专长进度。
- 不同子类可分别计算每日上限。
- 未启用宠物/育儿主题时相关成就不出现在列表和推荐中。
- 自定义名称不能通过改名绕过分类或刷专长。
- 时长型成就只使用校验后的 `actualMinutes`。
- 删除、10 秒撤销和类别修改可以进入 DIRTY 并重建到正确结果。

### 实际交付

- 已实现 10 条专长系列、30 个铜/银/金独立定义的异步计算与跨级批次聚合。
- 次数型规则按“成员 + 家庭本地日 + 标准子类”最多计入 3 次；第 4 条家务仍正常入账。
- 时长型专长只累计 `1...180` 分钟内、由服务端验证后的 `actualMinutes`；创建接口拒绝客户端 `occurredAt`。
- 自定义家务只使用显式标准类别映射，不读取名称或关键词；无法可靠映射的子类不进入专项统计。
- 宠物、育儿和恋爱专长跟随家庭常用布局中的主题启用状态显隐和计算。
- 删除和 10 秒撤销通过事件 worker 将相关进度标记为 DIRTY 后按当前有效记录重建；历史已解锁徽章不回收，展示值不倒退。
- iOS 已补齐 10 条专长系列的名称、说明、解锁文案和等级展示，API 仍是唯一判定源。
- 后端新增纯逻辑单测和阶段 5 e2e，覆盖每日上限、主题显隐、铜银金跨级解锁、删除/恢复重建和 `occurredAt` 拒绝。

## 11. 阶段 6：家庭互动、协作与搭档

### 目标

增加家庭共同荣誉，但不展示“谁做得最多”。

### 工作内容

- 实现 3 个个人回应成就及每日关系计入上限。
- 周期开始时根据全部 ACTIVE 成员生成资格快照。
- 实现家庭成立、全员出动、家庭接力赛、一条龙服务和分类覆盖。
- 实现首个搭档成就 `PAIR_COOK_AND_CLEAN`，规范化成员组合。
- 保存家庭成就参与者与叙事摘要。
- 成就结果通过页面查询与刷新展示；通知留待统一通知系统阶段。

### 验收

- 非 ACTIVE 成员不进入家庭门槛，周期中成员状态变化不重写当前快照。
- 单人家庭不返回不可达家庭/搭档成就。
- A+B 与 B+A 只能解锁一次，A+B 与 A+C 可以分别解锁。
- 两名成员并发完成家庭成就，只产生一条解锁。
- 自己回应自己、重复切换表情不会刷互动进度。
- 家庭详情只讲共同故事，不展示精确贡献比例和成员差距。

### 实际交付

- 已实现 `REACTION_FIRST`、`REACTION_GIVEN_20`、`REACTION_RECEIVED_10` 三项个人互动成就；自己回应自己不计入，表情切换不重复累计，同一发送者到同一接收者按家庭本地日最多计入 3 次。
- 已实现家庭成立、全员出动、家庭接力赛、无人隐身、一条龙服务和家务全图鉴六项家庭协作成就。
- 周/月资格使用 `AchievementEligibilitySnapshot` 冻结 ACTIVE 成员；同一周期后续加入或退出不重写已有快照。
- 已实现 `PAIR_COOK_AND_CLEAN`，成员 ID 排序后作为唯一搭档键，A+B 与 B+A 只会解锁一次，不同搭档组合可分别解锁。
- 家庭解锁保存参与人和叙事摘要，只返回共同完成信息，不计算或展示成员贡献比例。
- 成就查询已合并个人、家庭和当前成员相关的搭档成果；单人家庭隐藏阶段六不可达卡片。
- worker 的并发排空调用会等待同一个进行中任务，避免测试或手动同步在后台轮询时提前返回。
- 通知仍按冻结决策留待统一通知系统阶段，本阶段通过现有页面刷新和批次反馈展示结果。
- 后端 build、34 项 Jest、19 项 e2e 全部通过；iOS Simulator XCTest 66 项通过、1 项 Keychain 环境用例跳过、0 失败。

## 12. 阶段 7：长期里程碑、彩蛋与上线保障

> 状态：本地工程验收完成（2026-08-11）。migration：`20260811190000_add_achievement_archive_lifecycle`。真实生产环境的外部告警接入、数据库备份/恢复演练和 TestFlight 家庭灰度仍属于发布操作，不冒充为本地代码完成项。

## 13. 测试矩阵

每阶段至少包含：

- **单元测试**：时间算法、规则判定器、容量计算、推荐排序、DTO 解码。
- **后端 e2e**：权限、事件写入、幂等、并发、删除重建、成员生命周期。
- **Smoke**：现有 19 项主链路保持通过，并增加不阻塞业务的成就健康检查。
- **iOS XCTest**：ViewModel 状态、缓存、PENDING、批次解锁、Mock/API 分流。
- **手测**：双账号、单人家庭、深色模式、VoiceOver、弱网和服务不可用。
- **CI**：迁移、seed、build、Jest、e2e、smoke、iOS build/XCTest。

## 14. 推荐提交与发布策略

- 每个阶段独立分支和 PR；数据库 migration 与其业务代码同 PR。
- 阶段 1 至 3 使用 feature flag，先在 CI 和本地测试家庭开启。
- 第一次可演示里程碑是“阶段 3 后端闭环 + 阶段 4 iOS 基础体验”。
- 阶段 5、6、7 可以逐个开放，不阻塞首版成长旅程上线。
- 所有规则变更新增 definitionVersion，不直接覆盖已发布门槛。

建议里程碑：

| 里程碑 | 包含阶段 | 可验收结果 |
| ---- | ---- | ---- |
| M0 数据底座 | 0–2 | 事件可写入、消费、重试和审计，但用户界面不变化 |
| M1 成长闭环 | 3–4 | 用户可看到首记和 3/5/7 日进度，奖励自动生效 |
| M2 个人成就 V1 | 5 | 成长旅程和核心专长完整可用 |
| M3 家庭成就 V1 | 6 | 互动、协作和首个搭档成就可用 |
| M4 上线候选 | 7 | 长期里程碑、彩蛋、监控、灰度和恢复演练完成 |

## 15. 最终完成定义

只有同时满足以下条件，才能把成就系统标记为“已完成”：

1. 产品、iOS、后端、测试使用同一套 Key、门槛和规则版本。
2. 核心家务主流程不依赖成就服务可用性。
3. 并发和重试不会重复解锁或发奖。
4. 删除、10 秒撤销、禁止补记、成员变化和时区变化均通过验收。
5. 个人进行中进度保持私密，已解锁成就遵循用户可见性选择。
6. 家庭成就不展示成员排名、贡献比例或负向文案。
7. 权益可解释、可审计、可对账，Premium 到期不会删除数据。
8. CI、灰度、监控、回滚和数据重建演练全部完成。
