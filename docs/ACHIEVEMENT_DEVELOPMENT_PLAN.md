# 成就系统整体开发与验收计划

更新时间：2026-08-10

## 1. 文档定位

本计划把 [家庭家务成就系统完整开发文档](./家庭家务成就系统完整开发文档.md) 转换为适合当前仓库执行的工程阶段、交付物和验收门槛。

事实来源优先级：

1. 用户后续明确确认的规则。
2. `家庭家务成就系统完整开发文档.md`。
3. 本实施计划。
4. 旧版 `ACHIEVEMENTS.md`。
5. 当前尚未适配成就系统的代码。

成就系统是增量能力。现有登录、家庭、家务记录、积分、互动、排行、月报和软删除主链路不得被破坏。

## 2. 当前项目基础

已经具备：

- NestJS + Prisma + PostgreSQL 后端，以及 migration、seed、Jest、e2e 和 smoke test。
- SwiftUI + MVVM、Mock/API 切换、Keychain、环境配置和 XCTest。
- 家庭 `timezone`，可用于家庭本地日、周和月份范围。
- 稳定 `userId + familyId` 成员关系，退出后使用 `LEFT` 保留历史。
- 家务记录软删除、实际耗时、标准主题/大类、回应和创建者快照。
- 免费/高级版常用家务与自定义家务容量规则。

尚未具备：

- 成就定义、事件、进度、解锁、奖励账本和审计表。
- 服务端生成的业务发生时间 `occurredAt` 与禁止补记校验。
- 基于现有 ACTIVE 成员的周期资格快照。
- 成就 Outbox、异步处理器、重试、死信和进度重建。
- 家务记录 10 秒撤销接口和生产监控。
- 成就查询 API、iOS 页面、解锁反馈和本地缓存。

## 3. 开发前必须冻结的决策

以下决策已于 2026-08-10 冻结，后续实现必须使用同一口径：

| 决策 | 冻结口径 | 当前实现差距 |
| ---- | ---- | ---- |
| 高级版自定义家务上限 | 产品显示“不限”；每家庭最多 100 个未归档项目作为服务端内部保护，上限可配置 | 当前代码仍为 10 项，实施阶段需统一后端、iOS、PRD 和营销页 |
| 业务发生时间 | V1 不允许补记；`occurredAt` 由服务端创建记录时生成，旧数据以 `createdAt` 回填 | 当前只有 `createdAt` |
| 参与角色 | 不新增 `PARTICIPANT/OBSERVER`；全部 ACTIVE 成员参与适用的家庭成就 | 复用现有 status 即可 |
| 删除恢复 | 删除后提供 10 秒“撤销”，不做回收站，超时后不允许用户恢复 | 当前只有软删除，没有恢复接口 |
| 通知 | V1 暂不做；登记到后续统一通知系统，届时一并设计应用内通知和 Push | 当前无正式通知系统 |
| 家庭排行榜 | 保留现有积分排行榜；成就系统不新增排名型、输赢型或差距型成就 | 无需移除现有排行榜 |
| 规则执行方式 | 家务立即成功；数据库 Outbox + 同仓库 worker 异步结算成就，首版不引入 Redis | 尚未实现成就事件管道 |

任何变更都必须先更新完整说明书、规则版本和验收用例，不能在代码中悄悄形成第二套口径。

## 4. 总体拆分

建议分为 8 个阶段。每一阶段单独提交、单独迁移、单独验收，不把整个系统塞进一个超大 PR。

```text
0. 规则冻结与数据字典
1. 数据模型与兼容迁移
2. 事件管道与幂等处理器
3. 个人成长与家庭权益纵向闭环
4. iOS 成就基础体验
5. 家务专长与防刷
6. 家庭互动、协作与搭档
7. 长期里程碑、彩蛋与上线保障
```

## 5. 阶段 0：规则冻结与数据字典

### 目标

把产品规则转换为不会歧义的 Key、枚举、标准分类和容量口径。

### 工作内容

- 解决第 3 节全部冲突项。
- 冻结 V1 Achievement Key、等级、门槛、归属和奖励。
- 为 36 项系统家务及自定义家务建立 `categoryCode/subcategoryCode` 映射。
- 明确活跃日、严格连续、25/30 习惯、禁止补记和时区规则。
- 定义 ACTIVE 成员周期快照和单人家庭规则。
- 明确 V1、V1.1 与不做范围。
- 将最终规则同步到 PRD、API、验收矩阵和 seed 设计。

### 交付物

- Achievement Key 清单和规则版本 `definitionVersion=1`。
- 家务标准分类映射表。
- 冲突决策记录。
- 后端 DTO/API 草案和 iOS DTO 草案。

### 验收

- 产品、后端、iOS、测试使用完全相同的 Key 和门槛。
- 任何成就都能回答：归谁、统计什么、时间窗口、上限、防刷、奖励和可见性。
- 现有免费/高级版容量只有一套明确口径。
- 没有把当前排行榜误删，也没有在成就页面增加成员比较。

## 6. 阶段 1：数据模型与兼容迁移

### 目标

建立可审计、可重建、可版本化的数据底座，保持现有数据可用。

### 工作内容

- `ChoreRecord` 增加 `occurredAt`，旧数据用 `createdAt` 回填。
- 新增 Definition、Event、Progress、UnlockBatch、Member/Family/Pair Achievement。
- 新增 EligibilitySnapshot、FamilyRewardGrant、AuditLog。
- 新增 10 秒撤销所需的记录恢复接口和服务端时间窗口校验，不增加回收站表或列表页。
- 增加完整唯一索引、外键、状态枚举和查询索引。
- seed 写入 V1 成就定义，重复 seed 不产生重复数据。
- 增加总开关 `ACHIEVEMENTS_ENABLED=false`，迁移后默认不影响用户。

### 验收

- `prisma validate`、`prisma generate`、migration deploy 和 seed 通过。
- 在现有数据库副本上迁移成功，记录、家庭、点赞和月报数量不变。
- migration 可重复部署但不会重复插入定义或奖励。
- 所有唯一约束有并发测试或数据库级验证。
- 开关关闭时，现有 smoke test 19/19 保持通过。

## 7. 阶段 2：事件管道与幂等处理器

### 目标

让成就失败不阻塞家务主流程，并且事件可重试、可审计、可重放。

### 工作内容

- 家务创建/删除/10 秒撤销、回应、成员加入/退出和套餐变化同事务写入 Outbox。
- 实现数据库轮询 worker、事件认领、超时释放、指数退避和失败状态。
- 实现规则注册表、受影响规则筛选和幂等消费骨架。
- 实现 `PENDING | PROCESSING | SUCCEEDED | FAILED` 状态和查询接口。
- 建立死信查看、人工重放和基础审计命令。
- 核心接口立即返回业务成功和成就 `PENDING`；不得等待成就计算或要求重记家务。

### 验收

- 同一业务请求重试 10 次，只产生 1 个业务结果和 1 个有效事件。
- 同一事件消费 10 次只更新一次进度。
- worker 停止时家务仍可创建；恢复后可自动补算。
- 唯一冲突被视为已处理，不返回 500。
- 失败事件保留错误码、重试次数和可重放信息。

## 8. 阶段 3：个人成长与家庭权益纵向闭环

### 目标

先完成最有留存价值的一条端到端闭环，再扩展完整目录。

### 首批范围

- `FIRST_RECORD`
- `ACTIVE_DAYS_3`
- `ACTIVE_DAYS_5`
- `ACTIVE_DAYS_7`
- `STREAK_7`
- `STREAK_14`
- `HABIT_30`

### 工作内容

- 实现家庭时区下的个人活跃日、严格连续和滚动 25/30 计算。
- 实现 MemberAchievement、Progress、UnlockBatch 和 FamilyRewardGrant 原子写入。
- 容量计算从固定数字改为“套餐基础 + 永久成就奖励”。
- 同一成员可获得个人徽章，同一家庭只获得一次相同容量奖励。
- 删除只回退尚未解锁的真实进度，不撤销已解锁荣誉和奖励。
- 提供 summary/me/detail/visibility API 和创建家务的 evaluation 响应。

### 验收

- 3/5/7 使用累计活跃日，不要求连续；7/14 使用严格连续。
- 同一天多条记录只增加 1 个活跃日。
- A、B 都能获得个人成就，但家庭容量只增加一次。
- 并发触发不会重复解锁或重复扩容。
- 成员退出不带走家庭奖励；进入新家庭后按新关系重新计算。
- 删除触发记录后，已发奖励不回收，未解锁进度可正确重建。
- 免费版容量在接口、iOS限制和高级版营销页中一致。

## 9. 阶段 4：iOS 成就基础体验

### 目标

提供完整但安静的成就体验，不增加第五个 Tab，不打断记录家务。

### 工作内容

- 新增成就 DTO、APIClient 方法和 AppViewModel 状态。
- Home 增加“下一项成就”轻入口；Profile 增加永久入口。
- 新增 AchievementsView、分类列表、收藏柜和详情 Sheet。
- 支持进行中、已解锁、隐藏、同步中、空状态和错误状态。
- 实现同批次聚合庆祝层和奖励自动到账文案。
- Mock 模式提供固定成就数据；API 模式以服务端为唯一判定源。
- 本地缓存最近一次成功数据，明确显示更新时间。
- 支持深色模式、Dynamic Type、VoiceOver 和减少动态效果。

### 验收

- 没有新增底部 Tab；家务记录流程不增加必经步骤。
- 客户端不能通过本地修改直接解锁或发奖励。
- evaluation 为 PENDING 时记录仍显示成功，成就显示“同步中”。
- 一次解锁多个成就只出现一个聚合反馈，不连续弹窗。
- 单人家庭不显示大片不可达家庭/搭档锁卡。
- iOS build、Preview 和 XCTest 全部通过。

## 10. 阶段 5：家务专长与防刷

### 目标

上线次数、时长和类别覆盖三类个人专长，并保证可信度。

### 工作内容

- 实现洗碗、烹饪、垃圾、宠物、育儿、地面、洗护、恋爱、收纳和六边形专长。
- 支持铜、银、金独立解锁和跨级批次聚合。
- 同成员、同标准子类、同自然日最多计入 3 次。
- 未启用主题不展示、不推荐、不计算。
- 自定义家务只根据标准映射统计，不解析用户标题关键词。
- 实现时长异常范围，以及拒绝客户端传入 `occurredAt` 的校验。

### 验收

- 同子类第 4 条记录仍是有效家务，但不增加专长进度。
- 不同子类可分别计算每日上限。
- 未启用宠物/育儿主题时相关成就不出现在列表和推荐中。
- 自定义名称不能通过改名绕过分类或刷专长。
- 时长型成就只使用校验后的 `actualMinutes`。
- 删除、10 秒撤销和类别修改可以进入 DIRTY 并重建到正确结果。

## 11. 阶段 6：家庭互动、协作与搭档

### 目标

增加家庭共同荣誉，但不展示“谁做得最多”。

### 工作内容

- 实现 3 个个人回应成就及每日关系计入上限。
- 周期开始时根据全部 ACTIVE 成员生成资格快照。
- 实现家庭成立、全员出动、家庭接力赛、一条龙服务和分类覆盖。
- 实现首个搭档成就 `PAIR_COOK_AND_CLEAN`，规范化成员组合。
- 保存家庭成就参与者与叙事摘要。
- 成就结果通过页面查询与刷新展示；通知留待统一通知系统阶段。

### 验收

- 非 ACTIVE 成员不进入家庭门槛，周期中成员状态变化不重写当前快照。
- 单人家庭不返回不可达家庭/搭档成就。
- A+B 与 B+A 只能解锁一次，A+B 与 A+C 可以分别解锁。
- 两名成员并发完成家庭成就，只产生一条解锁。
- 自己回应自己、重复切换表情不会刷互动进度。
- 家庭详情只讲共同故事，不展示精确贡献比例和成员差距。

## 12. 阶段 7：长期里程碑、彩蛋与上线保障

### 目标

完成 V1 长期内容和生产级可靠性。

### 工作内容

- 实现家庭活跃日、记录数、周年里程碑和 5 个隐藏彩蛋。
- 完成退出、重新加入、家庭解散、账号注销和匿名化规则。
- 完成 DIRTY 重建、对账任务、死信重放和奖励缓存校验。
- 接入产品指标、负面指标、性能、失败率和积压监控。
- 以家庭为单位灰度，提供总开关、规则版本回滚和重建演练。
- 建立上线后 1/7/30 日观察表和异常记录告警。

### 验收

- 完整通过原说明书第 22 节全部规则、归属、并发、删除、时间和降级用例。
- 家庭时区午夜、DST 和时区变更不产生重复业务日或回写历史解锁。
- 解锁和奖励账本每日对账一致。
- 成就 worker 完全不可用时，登录、记录、点赞、排行和月报仍正常。
- 灰度关闭后停止新评估，但不破坏历史成就读取。
- 完成数据库备份、回滚、事件重放和进度全量重建演练。

## 13. 测试矩阵

每阶段至少包含：

- **单元测试**：时间算法、规则判定器、容量计算、推荐排序、DTO 解码。
- **后端 e2e**：权限、事件写入、幂等、并发、删除重建、成员生命周期。
- **Smoke**：现有 19 项主链路保持通过，并增加不阻塞业务的成就健康检查。
- **iOS XCTest**：ViewModel 状态、缓存、PENDING、批次解锁、Mock/API 分流。
- **手测**：双账号、单人家庭、深色模式、VoiceOver、弱网和服务不可用。
- **CI**：迁移、seed、build、Jest、e2e、smoke、iOS build/XCTest。

## 14. 推荐提交与发布策略

- 每个阶段独立分支和 PR；数据库 migration 与其业务代码同 PR。
- 阶段 1 至 3 使用 feature flag，先在 CI 和本地测试家庭开启。
- 第一次可演示里程碑是“阶段 3 后端闭环 + 阶段 4 iOS 基础体验”。
- 阶段 5、6、7 可以逐个开放，不阻塞首版成长旅程上线。
- 所有规则变更新增 definitionVersion，不直接覆盖已发布门槛。

建议里程碑：

| 里程碑 | 包含阶段 | 可验收结果 |
| ---- | ---- | ---- |
| M0 数据底座 | 0–2 | 事件可写入、消费、重试和审计，但用户界面不变化 |
| M1 成长闭环 | 3–4 | 用户可看到首记和 3/5/7 日进度，奖励自动生效 |
| M2 个人成就 V1 | 5 | 成长旅程和核心专长完整可用 |
| M3 家庭成就 V1 | 6 | 互动、协作和首个搭档成就可用 |
| M4 上线候选 | 7 | 长期里程碑、彩蛋、监控、灰度和恢复演练完成 |

## 15. 最终完成定义

只有同时满足以下条件，才能把成就系统标记为“已完成”：

1. 产品、iOS、后端、测试使用同一套 Key、门槛和规则版本。
2. 核心家务主流程不依赖成就服务可用性。
3. 并发和重试不会重复解锁或发奖。
4. 删除、10 秒撤销、禁止补记、成员变化和时区变化均通过验收。
5. 个人进行中进度保持私密，已解锁成就遵循用户可见性选择。
6. 家庭成就不展示成员排名、贡献比例或负向文案。
7. 权益可解释、可审计、可对账，Premium 到期不会删除数据。
8. CI、灰度、监控、回滚和数据重建演练全部完成。
