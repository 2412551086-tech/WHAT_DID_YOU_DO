# 家庭保卫战成就视觉设计指南

更新时间：2026-08-11
状态：V1 视觉方向已生成 47 张卡片预览，正式 App 资源接入前仍需微调

## 1. 文档目标

本指南用于指导成就插画、收藏柜、进度卡和解锁反馈的后续设计。它提取用户提供案例中有效的视觉机制，但不复制案例中的人物、构图、名称或具体美术资产。

当前 App 仍使用 SF Symbols 作为功能占位。设计输出已覆盖 7 张成长、30 张专长等级、3 张回应、6 张家庭协作和 1 张搭档卡片；这些预览需要完成风格微调后再进入 Asset Catalog。

V1 设计输出位置：

```text
design-output/achievements/v1-core/
├── illustrations/                         # 27 张可复用透明主体插画
├── cards/                                 # 47 张成就卡片预览

└── achievement-v1-47-card-contact-sheet.jpg
```

`design-output/` 保持 Git 忽略；正式确认后的压缩资源才进入 `Assets.xcassets/Achievements`。

## 2. 对参考案例的核心分析

### 2.1 紧凑成就矩阵

有效之处：

- 每项成就都有一个明确角色、动作或故事，不依赖抽象勾选图标。
- 插画本身形成不规则轮廓，没有被统一圆章或盾牌束缚。
- 大数字与插画结合，强化目标量级和解锁价值。
- 高饱和主色用于区分成就，白色页面保留足够呼吸感。
- 三列结构适合快速扫描，标题和进度是插画之后的第二、第三层信息。

风险：

- 角色比例和表情偏卡通，直接照搬会让本产品显得低幼。
- 数字直接绘制进图片不利于本地化、动态门槛和后续规则调整。

### 2.2 全画幅收藏卡

有效之处：

- 插画不是装饰，而是卡片的主要内容，收藏感明显强于普通徽章墙。
- 允许不同场景、视角和艺术题材，避免所有成就看起来只是换颜色。
- 稀有度、类别和完成状态放在次级信息区，不抢插画主视觉。
- 大面积画面能承载“经历”和“记忆”，适合高价值或长期成就。

风险：

- 完全不同的绘画媒介会削弱产品品牌一致性。
- 全部使用大卡片会降低浏览效率，不适合几十项成就的主列表。

### 2.3 横向进度卡

有效之处：

- 主体插画越出卡片边界，产生动势和立体层次。
- 每张卡只有一个主色，标题、进度和百分比层级清晰。
- 人物或场景承担情绪，进度条承担功能，两者没有互相干扰。
- 适合“进行中”列表，比锁住一整墙灰色徽章更有行动感。

风险：

- 卡片颜色过多时会互相抢戏。
- 插画尺寸和越界范围不统一会导致列表节奏混乱。

## 3. 新的设计结论

### 3.1 核心方向

采用 **“家庭战报叙事贴纸”**，而不是“统一奖牌外框”。

每项成就是一幅透明背景的独立叙事插画：一个动作、一个家务场景或一个有记忆点的物件组合。插画允许不规则外轮廓，通过白色裁切边形成冰箱贴效果；UI 容器负责标题、数字、进度和状态。

### 3.2 成熟度控制

- 人物使用中度抽象比例，避免大头、婴儿脸和夸张卖萌。
- 动作要有力量、方向和明确重心，不使用僵硬站姿。
- 表情克制，以专注、轻松、得意和稳定为主。
- 保留扁平糖果色，但加入少量纸张颗粒、套色错位或二段阴影，提升收藏质感。
- 不使用写实金属奖牌、游戏宝箱、王冠堆叠或廉价发光特效。

### 3.3 视觉层级

1. 叙事插画：负责吸引和情绪。
2. 成就名称：负责理解。
3. 当前值/目标值和进度条：负责行动反馈。
4. 奖励、稀有度和可见性：作为次级信息。

数字和标题由 SwiftUI 渲染，不绘制进 PNG，避免门槛变化后重做资产。

## 4. 统一视觉语言

### 4.1 插画规范

- 原稿：透明背景 `1024 × 1024 PNG`。
- 主体安全区：四周至少保留 8%，避免在卡片和网格中裁切。
- 视觉占比：主体覆盖画布约 78%...86%。
- 轮廓：深墨色圆角线，1024 原稿等效约 18...24 px。
- 裁切边：主体外侧 24...32 px 暖白贴纸边，禁止额外黑色外框。
- 阴影：资产本身不带投影；由 SwiftUI 根据使用场景统一添加。
- 细节：缩小到 64 pt 时仍能辨认主要动作，不依赖小字和细碎物件。

### 4.2 色彩规范

- 奶油白 `#FFF9E8`
- 品牌黄 `#FFD633`
- 信息蓝 `#63B8FF`
- 薄荷绿 `#6EDB9A`
- 珊瑚红 `#FF6B5B`
- 糖果粉 `#F56BB7`
- 淡紫 `#C0A1FF`
- 深墨色 `#111111`

单幅插画最多使用一个主色、两个辅助色。白色/奶油色和中性色应占主要面积，避免七张图同时成为高饱和色块。

### 4.3 允许变化的部分

- 主体可以是人物动作、双手、家庭空间或标志性物件。
- 构图可以是斜向、环形、前后层叠或横向动作。
- 不同成就应有不同剪影，不强制套入圆形、盾牌或花边章。

### 4.4 必须统一的部分

- 同一轮廓粗细、同一白色贴纸边、同一颜色体系。
- 相同抽象程度和纸张颗粒强度。
- 相同光源方向，不使用写实高光。
- 同一批次人物不能出现完全不同的头身比或绘画媒介。

| --- | --- | --- | --- | --- | --- |

| `achievement_active_days_5` | 五日渐入佳境 | 人物推着装有不同家务工具的小车稳步前进，身后五张完成票形成上扬轨迹 | 推车 + 上扬票据 | 薄荷绿 | 用五颗星围着一只手套 |
| `achievement_active_days_7` | 七日成习 | 人物在冰箱上贴下最后一枚本周功劳贴，周围已经形成一圈有节奏的彩色贴纸 | 伸手动作 + 环形贴纸 | 珊瑚红 | 与连续七日使用同一条链条语言 |

| `achievement_streak_14` | 两周稳稳当当 | 两名手部或同一人物完成一次接力，把第二组家务票稳稳接到第一组后面 | 双段接力 + 稳定支点 | 淡紫/黄 | 只叠放两张日历纸 |
| `achievement_habit_25_30` | 习惯养成 25/30 | 人物站在几乎贴满功劳票的冰箱前检查最后几个空位，整体像一面家庭战绩墙 | 人物背影 + 大面积战绩墙 | 金黄 + 薄荷绿 | 在图片里直接写 `25/30` |

### 5.1 累计与连续的区分

- `ACTIVE_DAYS_*` 使用“收集、增加、逐步丰富”的视觉语言，完成票可以分散或形成上扬趋势。
- `STREAK_*` 使用“不断裂、接力、连续连接”的视觉语言，必须看出中间没有断点。
- 两类成就不能只通过颜色或数字区分。

## 6. UI 使用方式

### 6.1 进行中列表

- 使用横向进度卡。
- 插画位于左侧，占卡片宽度约 34%...38%，允许越出卡片左边和顶部 8...14 pt。
- 右侧展示名称、当前值/目标值、进度条和奖励摘要。
- 每张卡只使用一种低饱和背景色，不使用独立硬阴影。

### 6.2 收藏柜

- iPhone 使用两列自适应网格，不建议三列挤压当前较长的中文名称。
- 插画作为主要内容，卡片背景保持奶油白或透明，不套统一奖牌底座。
- 名称在插画下方；解锁日期和可见性放入详情页，不挤在网格里。
- 长期可以增加“人生、专长、关系、隐藏”筛选，不把筛选绘制进资产。

### 6.3 详情页

- 使用同一张 1024 原稿放大展示，不另画详情插图。
- 上半区为大图和名称，下半区为解锁条件、当前进度、奖励和可见性。
- 稀有成就可以由 SwiftUI 增加轻微光晕或纸屑反馈，不能修改原始资产。

### 6.4 解锁反馈

- 聚合解锁时只展示本批次第一张插画，其余以名称列表呈现，避免连续弹窗。
- 动画为贴纸落下、轻微回弹和一次触感反馈，时长控制在 0.45...0.7 秒。
- 开启“减少动态效果”时改为淡入，不使用位移和缩放。

## 7. 锁定、进度与稀有度

### 7.1 锁定状态

不制作灰色 PNG。SwiftUI 统一处理：

- 饱和度降低至约 15%。
- 不透明度约 42%...52%。
- 可叠加轻微材质雾层，但不能模糊到无法识别。
- 锁图标属于 UI 状态，不绘制进插画。

### 7.2 稀有度

首批成长成就不使用铜银金。可通过很克制的 UI 标记区分：

- 普通成长：无额外标记。
- 严格连续：细蓝紫高光或“稀有”文字标签。
- 永久容量奖励：黄色礼物标记。

阶段五的铜、银、金专长复用同一主体插画，由 SwiftUI 或统一边饰改变材质，不重新设计三套完全不同的主体。

## 9. 下一轮视觉探索方法

不立即重画全部七张。先选择三项作为风格压力测试：

1. `功劳簿开张`：验证单一动作和品牌记忆点。
2. `一周没掉线`：验证横向连续叙事和小尺寸识别。
3. `习惯养成 25/30`：验证复杂场景和高价值收藏感。

三张通过后冻结以下内容：人物比例、线宽、贴纸边、颗粒、主色占比、动作强度和卡片越界范围，再生成其余四张。这样比一次重画七张更容易得到稳定风格。

## 10. 验收清单

- [ ] 第一眼像“值得收藏的成就插画”，不是儿童奖励贴。
- [ ] 七项在不看标题时仍能通过剪影和动作相互区分。
- [ ] 累计活跃与严格连续使用不同的视觉语法。
- [ ] 64 pt 下主体可识别，没有依赖文字和微小细节。
- [ ] 1024 原稿具有真实透明背景和完整 alpha 边缘。
- [ ] 白色贴纸边均匀，没有黑边、色块溢出或裁切残缺。
- [ ] 浅色、深色背景下均有足够对比度。
- [ ] 进行中卡、收藏网格和详情页可以复用同一资产。
- [ ] 锁定状态由代码生成，不存在第二套灰色图片。
- [ ] 没有复制参考案例中的人物、具体场景或构图。
