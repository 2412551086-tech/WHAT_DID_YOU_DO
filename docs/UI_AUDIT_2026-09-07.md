## 2026-09-07 登录页第二轮调整

- 欢迎页操作顺序改为“创建新家庭 / 加入已有家庭”在上，“登录已有账号”在下；横向边距缩小，两个家庭入口获得更宽的可点击容器。

- 登录方式简化为“邮箱登录”和“Apple 登录”；开发环境登录不再显示在登录 UI，底层测试能力没有删除。

- 深色登录页暂未写入 App。已生成两个候选预览：A 为原家务插画深色适配，B 为内购协作插画深色适配，等待选定后实施；当前 App 图标占位方案将被替换。
- 多登录方式不采用自动账号合并。绑定与误登录迁移规则已补充到 `AUTH_IDENTITY.md`；第一阶段应实现受认证的身份列表与绑定接口，已误建成两个 `User.id` 的情况进入独立迁移流程。

## 结论

目前主要问题不是插画不好看，而是页面的布局约束、视觉语言和状态表达不统一。应先保证按钮始终可见、可点，再统一背景和操作区域，最后精简信息和复用插画。不建议一次重写所有页面。

## 登录页设计方向：根据用户补充截图修订

推荐以图 3 的整体感为视觉基准，结合当前真实登录功能与可靠的响应式布局。不是恢复旧版手机号流程，也不是把整张参考图片直接铺满屏幕。

图 3 更协调的原因是插画、按钮、背景都使用鲜艳色彩和粗黑线条；当前图 1 则像在海报上贴了一张表单，图 2 又叠加了第二套标题。问题主要在后加的遮罩、面板和布局，不需要因此淘汰原插画。

| 元素 | 后续修改方向 |
| --- | --- |
| 背景与插画 | 保留原有明亮、活泼的家务插画，不加全屏灰黑遮罩；深色模式单独适配，不简单整体压暗 |
| 品牌标题 | 只出现一次，标题和插画分离布局，避免裁切、重复及本地化困难 |
| 登录操作 | 去掉外层大卡片和卡片套卡片；按钮与插画处在同一视觉表面 |

## 订阅插画复用建议

这幅插画的核心是“一起做家务”，不仅适用于付费。推荐让它成为少量关键节点的品牌素材，而不是所有页面的背景。

| 场景 | 建议 | 优先级 |
| --- | --- | --- |
| 欢迎/登录首屏 | 浅色保留原家务插画；深色采用用户最终选择的 B 方案，使用协作插画的透明深色专用资源，替代孤立的 App 图标 | 已采用 |
| 创建家庭成功 | 使用精简裁切，配家庭名称与邀请按钮，不再叠加大面积装饰 | 高 |
| 邀请家人 | 体现协作，二维码/邀请码仍是视觉主角 | 高 |
| 第一次共同完成家务 | 用作庆祝内容，但不要每次记录都弹出 | 中 |
| 官网产品介绍、分享图品牌区域 | 统一 App 与网站风格；分享图必须优先真实数据 | 中 |
| 首页空状态 | 可用简化版本，尺寸克制；避免与欢迎页连续重复 | 低 |

不建议用于网络错误、账号注销、统计图背景，也不替换真实成员头像和个性化成就图标。目前素材为白底，深色模式需要专用适配；不能简单原图贴到深色页面。

## 推荐修改顺序与验收

1. 登录专项：浅色按图 3 的一体化方向保留原插画，深色使用 B 方案协作插画；调整欢迎、登录、邮箱 OTP 的屏幕约束/滚动/键盘/安全区；消除品牌重复和背景割裂；不改认证业务。
2. 交互安全：扩大点击范围，纠正返回即退出账号，处理底部浮层；验证创建、加入、恢复登录。
3. 统一主题：系统字体及大字号、浅深色、颜色对比、表面层级；订阅页按现有插画保留风格。
4. 内容精简：初次使用首页、家庭初始化、权益口径、月报对话、账号身份信息。
5. 订阅插画复用：先家庭创建成功和邀请家人两个场景，确认后再扩展；登录页保留原插画。

每一批单独检查，不一次覆盖全部页面。验收矩阵至少包含小屏 iPhone、常见 iPhone、较大 iPhone、iPad/横屏支持范围；浅深色、默认/最大辅助字号、键盘打开、长中文/英文文本、错误提示、加载/禁用、离线、空数据与多成员。真机重点核查屏幕最下方按钮、连续点击、左右滑动和系统返回。

内购需另做真实产品加载、购买取消/失败、恢复购买、已订阅、到期和家庭共享权益的沙盒联调；UI 审查不代表内购功能已上线。
