# 通知系统审查方案

日期：2026-09-11。状态：用户已决定暂缓制作，方案保存备查；未实施、未部署、未申请用户通知权限。

建议同时建设本地通知和服务器推送，并用 App 内消息中心承载正式消息记录。两种发送方式负责不同事件，不对同一件事双重提醒。

## 2. 到底由谁发送

**本地通知：App 在用户手机上登记时间，由 iOS 到时展示。** 已排定的提醒不需要你的服务器执行，也不需要当时打开 App；未登录用户也能使用。用户授权、系统设置与专注模式仍影响展示。

**服务器通知：你的服务器判断事件和接收人，提交给 Apple APNs，由 APNs 投递到手机。** 不是你的服务器直接向 iPhone 弹窗。需要账号、设备 token 和 Apple 推送能力。已有邮箱验证码邮件属于另一条邮件通道，本期不默认增加邮件/短信提醒。

**消息中心：保存可查询、可标记已读的消息。** 账号消息放服务器，多设备共享已读状态；本地成就消息放本机，按本机家庭隔离。关闭系统通知不影响查看消息中心。

本地和远程通知通常共用 App 的系统通知授权，不应弹两套授权请求。APNs 接受请求不等于用户已收到或已阅读；消息中心才是可靠的查询入口，不承诺推送必达。

## 3. 通知清单与建议默认值

表内“推送开启”均以用户主动允许系统通知为前提；偏好默认值不等于首次启动立即申请权限。

| 通知 | 来源与接收人 | 建议默认值及行为 | 首期 |
| --- | --- | --- | --- |
| 个人记录提醒 | 本地，仅当前手机用户 | 默认关闭；主动设定时间后每天一次，建议初始时间 20:30；文案中性，不断言今天没做家务 | 是 |
| 加入家庭申请 | 服务器，当前有审批权限的管理员 | 消息中心 + 推送；同一申请只通知一次 | 是 |
| 加入通过/拒绝 | 服务器，申请人 | 消息中心 + 推送；拒绝不在锁屏展示理由 | 是 |
| 新成员加入 | 服务器，其他在籍成员 | 默认仅消息中心，不与申请通过通知重复提醒本人 | 是 |
| 家务完成 | 服务器，其他在籍成员 | 默认不推送；消息中心合并为家庭摘要，原始逐条记录仍在家庭动态 | 是 |
| 收到点赞或其他反应 | 服务器，记录作者 | 默认仅消息中心；同一记录短时间聚合，撤销/反复切换不刷消息 | 是 |
| 个人成就解锁 | 本机工作区本地；账号工作区服务器 | 前台沿用已有庆祝反馈，不再弹系统横幅；消息中心保留。后台账号解锁可推送，同批合并一条 | 是 |
| 家庭成就解锁 | 服务器，仍有资格查看的在籍成员 | 消息中心；推送归入“成就与报告”开关，一批一条 | 是 |
| 上月报告可查看 | 服务器，家庭在籍成员 | 家庭时区每月 1 日 09:00 触发，按接收人免打扰延后；每家庭每月一次 | 第二步 |
| 指定家务/任务到期 | 本地个人规则；共享任务由服务器 | 先完成任务、负责人、重复规则和时区模型再接入，不从“常做家务”推断排班 | 后续 |
| 评论、存疑、积分兑换 | 服务器 | 等对应业务落地再定义，不制作无法跳转的通知 | 后续 |
| 长时间未做家务、排名落后 | 不发送 | 缺少记录不代表没做；不做羞辱、催促或制造家庭矛盾的推送 | 不做 |

月报当前没有预生成状态，首版文案必须是“上月报告可以查看了”，不能说“月报已生成”。触发任务先检查家庭有效成员和该月有效记录；点击复用现有报告接口。后续如改成报告快照，才引入真正的生成成功事件。

个人提醒采用固定时刻文案，例如“留一点时间，记下今天的付出。”首期不承诺“所有设备今天都没记录才提醒”：本地离线时无法获知其他设备状态。将来需要这个条件时，作为账号下独立的服务器提醒模式，与本地提醒互斥。

## 4. 打扰控制

- 推送默认免打扰 22:00–08:00，使用接收人设置的时区；家庭统计周期仍使用家庭时区。跨午夜、夏令时与旅行后的时区变更要分别测试。
- 静默时段照常生成消息中心记录，推送延后，过期或已处理消息丢弃，不在早上一次补发几十条。
- 普通互动按 15 分钟窗口聚合，最多每用户每天 3 条普通推送；加入申请等操作通知独立限流。明确由用户设置的本地提醒不计入普通推送额度。
- 成就同批只发一条；隐藏成就未解锁前不泄露名称或条件。本人完成家务，不再收到自己的“有人完成家务”推送。
- 推送重试复用同一逻辑事件 ID；消息中心以事件和接收人唯一约束去重。APNs 的 collapse/thread 标识辅助替换与分组，但不代替数据库去重，也不能承诺端到端 exactly-once。
- 已读、撤销、记录删除、申请已处理、成员离开后，取消未发送的相关通知；发送前再次检查权限。已经出现在系统通知中心的远程消息无法保证被所有设备即时撤回。
- 默认锁屏泛化文案，如“你有一条家庭新消息”，不放家庭名、姓名、记录内容、拒绝理由或验证码；详情进入 App 后鉴权读取。用户后续可选择详细预览。
- 不使用紧急提醒权限，不绕过专注模式，不默认添加营销通知。声音和角标独立可关。

## 5. 设置与交互

入口：我的 → 通知与提醒；消息中心作为独立列表入口，不新增长驻底部主标签。

设置包括系统权限状态、个人记录提醒开关与时间、家庭申请与审批、家庭动态摘要、互动消息、成就与报告、免打扰时段、声音、角标、锁屏详情。权限被拒绝时提供前往系统设置入口，不反复弹授权。

首次启动不索取权限。用户主动开启记录提醒或选择接收家庭消息时，先解释用途，再申请一次系统权限。授权被拒绝不影响家务和成就功能。

消息中心支持未读筛选、按家庭筛选、全部已读、分页及空/错误状态；角标仅表示当前账号的未读消息数，不把定时提醒次数加到角标。前台正在查看目标页面时，不额外弹同一消息的横幅。

点击通知先恢复登录状态，再按当前账号、家庭成员关系及目标资源权限路由。目标已删除、邀请已处理或无权访问时给出明确状态，不停在空白页面。第一版只做“查看”，不在锁屏直接审批或记录家务。

## 6. 本机、账号与多设备隔离

本地提醒绑定安装实例、本机家庭和规则 ID；账号消息绑定稳定 User.id、家庭与接收人，不使用邮箱作为消息身份。

登录选择页不自动迁移提醒。选云端后暂停本机家庭的提醒；退出账号后恢复原本开启的本机规则，不补发错过的提醒。主动上传本机家庭也不自动上传本机通知历史或复制一套相同提醒。

退出或换账号时立即清理设备上可控制的该账号待发/已显示通知、角标及缓存，并请求服务器撤销设备会话绑定。下次登录原子替换同一安装实例的绑定。离线退出存在撤销请求尚未到达服务器的时间窗，无法保证零迟到推送；因此锁屏内容默认泛化，打开时必须重新鉴权。不能把旧账号消息展示给新账号。

账号偏好云端保存，本地定时规则按设备保存；远程默认发给该账号所有有效设备，已读在 App 同步时更新。不要假称另一台离线设备上的系统横幅可以立刻消失。

## 7. 实施设计

沿用现有 NestJS + Prisma + PostgreSQL，不为第一版额外引入 Redis、商业推送平台或第二套用户身份。

新增独立通知模块，复用现有事务 outbox 的做法，不复用绑定成就语义的 AchievementEvent 表或处理器。

| 数据 | 作用 |
| --- | --- |
| NotificationOutbox | 业务事务中的待处理事件、唯一幂等键、重试时间、租约与失败原因 |
| Notification | 接收人、家庭、事件类型、受控目标、聚合键、已读和失效状态 |
| PushInstallation | 安装 ID、用户/会话绑定、token、环境、权限状态、最后活跃与撤销状态 |
| NotificationPreference | 分类开关、免打扰、时区、隐私与声音/角标偏好 |
| NotificationDelivery | 每通知/设备的提交状态、APNs 响应、重试和过期时间；不将 accepted 标为 delivered |
| 本机提醒配置 | 本机家庭/规则 ID、时刻、开关和已排定请求标识；仅存用户设备 |

后端在加入申请、审批、家务和反应事务中写通知事件；成就只在新解锁提交时发布，历史重算、批量导入与重放不补发旧推送。worker 使用数据库锁/租约防多实例重复消费；支持限次退避、过期丢弃、失败队列、管理重试与全局停发开关。不能只用内存计时器保存投递状态。

API 范围：登记/撤销当前安装、读取/更新偏好、分页查询通知、读取未读数、标记已读/全部已读。接收人身份从认证会话取得，客户端不可自行指定任意 userId 发消息；第一期不提供群发运营接口。

iOS 新增通知协调器，负责授权、token 更新上报、前台策略、点击路由、本地请求调度以及会话切换清理。系统权限以每次读取结果为准，不能依赖过期的 App 内开关。

上线需要 Apple App ID 开启 Push Notifications、重新签名并确认 aps-environment；服务器配置 APNs 签名凭据、Team ID、Key ID、bundle ID 与环境隔离。私钥只存服务器密钥配置，不放进 App 或仓库。普通可见推送不依赖静默后台刷新保证送达。

## 8. 实施与验收

第一步：完成本地记录提醒、通知设置、消息中心、加入申请/审批、互动及成就事件、APNs 投递和账号隔离。先内部设备灰度，不默认给现有用户打开推送。

第二步：月报可查看任务、用户主动开启的家庭动态推送摘要，以及投递与未读状态对账。再考虑共享任务提醒；不与第一版捆绑。

必须通过的验收：

1. 未登录、无网络、App 未打开时，已授权的定时本地提醒仍能按系统机制触发；关闭规则后不再排定。
2. 服务器事件触发后，即使接收人未打开 App，也能在两台签名真机验证远程通知；拒绝权限时仍能查询消息中心。
3. 同一事件重试、多实例竞争、APNs 超时、无效 token 不产生重复消息中心条目；不永久重试失效设备。
4. 本机→登录选择→云端→退出，以及账号 A→B、离线退出、家庭退出，都不暴露另一工作区的消息详情。
5. 免打扰、聚合限流、本人事件抑制、已处理取消、隐藏成就、删除后的点击路由正确。
6. 重启服务器不丢队列；关闭推送开关不影响家务主流程；日志不打印 token、私钥或敏感正文。
7. 前后台、冷启动、权限拒绝/撤销、时区变更、不同字体与深浅外观均验证。APNs 接受、设备收到与用户已读分别记录，不用模拟器截图代替真机投递验证。

验收完成之前，不在产品状态文档中标为正式通知系统已上线。

## 9. 本轮请审查

建议确认以下产品方向后再写业务代码：本地与服务器双通道；家务完成/点赞默认不逐条推送；22:00–08:00 免打扰；保留消息中心；本地提醒不随登录自动迁移；第一期不做营销、评论、存疑或催促式提醒。

以上均为建议默认值，尚未改动 App、数据库或生产配置。
