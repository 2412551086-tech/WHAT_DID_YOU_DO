# 《你今天干啥啦》UI 原型规划与提示词库 V2.1

> 用途：生成 Figma、HTML 或图片式高保真 UI 原型。  
> 依据：`docs/PRD.md`、`style.md`、`docs/STYLE_GUIDE_V2.md` 与已确认的产品设计决策。  
> 本文只定义页面结构、状态、人物占位和生成提示词，不修改业务逻辑。
>
> 2026-08-04 状态说明：当前实现使用“本周战况”、四主题家务库、主题圆环月报，以及可编辑家庭名称/成员近 30 天详情。本文以下主页面提示词已按当前产品结构校正。

## 0. 原型目标

首轮原型需要回答三个问题：

1. 四个主 Tab 是否像同一个产品，而不是四套不同主题。
2. 轻漫画、新粗野主义和系统玻璃是否达到“有记忆点但长期使用不累”的平衡。
3. 数据、操作、人物和互动是否能在 393×852 的真实 iPhone 页面中清楚共存。

四个主 Tab 的叙事：

1. **本周战况**：先看全家的本周战绩，再看我的贡献和家庭动态。
2. **记一下**：选择家务、调整实际耗时、确认积分。
3. **月度战报**：实时展示本月领先者、家庭总量、排行和家务结构。
4. **我的**：展示个人身份、家庭工具、OWNER 能力和必要设置。

## 1. 所有原型共用的设计约束

### 1.1 画布与布局

- iPhone 竖版，优先 393×852。
- 页面背景为奶油白 `#FFF9E8`，白色或奶油色占约 80%。
- 页面左右边距 20 pt，区块间距约 24 pt。
- 主页面允许纵向滚动，不能通过缩小字体把内容强塞进首屏。
- 底部必须为系统玻璃 Tab Bar 和 Home Indicator 留出安全区。
- 一页只设置一张视觉主卡，不使用卡片嵌套卡片。

### 1.2 视觉语言

- 产品性为基线，漫画感只来自人物、家务图形、贴纸和局部构图。
- 系统字体承担全部 UI 排版；标题可使用系统圆角粗体。
- 功能页使用 1-1.5 pt 轻描边和柔和悬浮阴影，不使用密集粗黑框。
- 系统玻璃只用于 Tab Bar、浮动工具按钮和 Sheet。
- 不为页面绑定固定分区色，使用全局语义色。
- 每屏最多使用一个主强调色和一个辅助色。
- 不使用紫蓝科技渐变、大面积透明卡、持续动画或廉价卡通字体。

### 1.3 统一底部导航

| Tab | 未选中 | 选中 |
| --- | --- | --- |
| 本周战况 | `sun.max` | `sun.max.fill` |
| 记一下 | `plus.circle` | `plus.circle.fill` |
| 月度战报 | `trophy` | `trophy.fill` |
| 我的 | `person.crop.circle` | `person.crop.circle.fill` |

- 四项等宽，中文标签始终显示。
- 图标约 22 pt、Medium 字重。
- 选中状态统一使用信息蓝，不按页面切换颜色。
- “记一下”与其他 Tab 保持同样尺寸，不制作凸起的巨大中间按钮。

### 1.4 人物占位

- 使用同一世界观的 6 个固定人物，2 女、2 男、2 中性。
- 1:4 头身比、中度抽象、极简五官，肤色和体型多样。
- 原型中人物保持独立图层；昵称、身份和数字不能烘焙进人物图片。
- MVP 每人只需要一张透明全身立绘，头像与半身由裁切获得。
- 人物固定色只用于人物识别，不代表页面、权限或状态。

### 1.5 状态与可用性

- 所有操作区域至少 44×44 pt。
- 禁用、错误、排名和选中状态不能只通过颜色表达。
- Loading 使用系统 ProgressView；错误使用浅珊瑚 Banner。
- 不显示未实现却看似可点击的入口。
- MVP 只设计浅色模式。
- 大字号时卡片纵向扩展；家务网格必要时可切换单列。

## 3. 四个主页面

## 3.1 本周战况

### 页面结构

1. 系统 Large Title“本周战况”。
2. 家庭本周总积分主卡：家庭总分为最大数字，附本周完成次数和累计分钟。
3. 个人战况条：我的本周积分、完成次数和家庭排名。
4. 家庭动态标题，右侧“查看全部”。
5. 最近 5 条家庭动态，按时间倒序；首屏可显示前几条，页面继续滚动。
6. 系统玻璃底部导航，选中“本周战况”。

本周主卡不放全身人物。动态支持拇指点赞、点赞数量和最多 3 个点赞成员小头像；可删除记录保留左滑能力，但主原型不常驻展示删除按钮。

### 主原型提示词

```text
设计《你今天干啥啦》的“本周战况”主页面。顶部使用系统 Large Title“本周战况”，不要漫画标题装饰。标题下方是一张全页唯一的家庭积分主卡，白色或奶油色底、22pt 圆角、轻描边和柔和悬浮阴影，只用亮黄做局部高光。卡内最大数字显示“家庭本周总积分 128”，右侧展示本周主要家务大类战线，底部显示完成次数和累计分钟，不放全身人物。

主卡下方是一条紧凑的个人战况区，清楚显示“我的本周积分 42”“完成 2 次”“家庭第 2 名”，保持白色内容面。再往下是分组标题“家庭动态”，右上角有轻量文字按钮“查看全部”。动态列表按时间倒序配置最近 5 条，每行位于同一个白色分组容器中：左侧 44pt 成员头像，中间显示“老妈 · 洗碗”和“20 分钟 · 8 分钟前”，右侧显示“+20 分”、SF Symbols 拇指点赞图标和数量；已点赞为亮黄填充，行底部显示最多 3 个点赞成员小头像和“+N”。列表行平面、使用分隔线，不为每一行添加独立阴影。

底部使用统一系统玻璃 Tab Bar，依次为太阳“本周战况”、加号“记一下”、奖杯“月度战报”、人像“我的”，当前太阳为填充选中状态。页面整体轻盈、留白充足、可以纵向滚动，首屏优先看到家庭总积分、个人战况和家庭动态开头。
```

### 补充状态

- 无本周记录时，主卡显示 0 分，战线为空状态保持清楚。
- 家庭动态为空时显示固定等待人物头像裁切、“本周还没有人记功”和“去记一下”。
- 局部加载失败只在动态分组显示错误 Banner，不遮挡家庭积分。

## 3.2 记一下

### 页面结构

1. 系统 Large Title“记一下”。
2. 家庭常用家务与自定义位置的两列网格。
3. OWNER 长按排序/置顶，页面底部继续上拉进入四主题家务库。
4. 系统玻璃底部导航，选中“记一下”。

系统家务全部免费；点击后进入耗时 Sheet，不直接创建记录。自定义家务作为家庭共享位置出现在同一网格中，不设置独立高级锁定区。

### 主原型提示词

```text
设计《你今天干啥啦》的“记一下”家务选择主页面。顶部采用系统 Large Title“记一下”，下方用一句简短辅助文案“刚干完什么？把功劳记上。”。主体使用稳定的两列常用家务网格，展示家庭已经选择的系统家务和自定义位置。每张家务卡为白色或奶油色内容面，14pt 圆角、1pt 轻描边和很弱的悬浮阴影，包含统一风格扁平图标、家务名称、标准时长和积分；名称控制在一行或稳定的统一高度，不因字数导致底部信息错位。

系统目录不设置高级锁定区。具备编辑权限的用户长按常用卡片可进入排序/置顶状态；页面滑到最底部继续上拉时，以一次轻触感反馈进入四主题家务库。家务库顶部依次为“日常家庭、恋爱陪伴、育儿、宠物”标签，选中卡片使用加深底色和勾选双重反馈。免费版最多 6 项并由 OWNER 同步全家；高级版不限数量且每位成员可个人定制。自定义额度分别为 2 / 10 个，常用页仅展示已有项和接下来的 2 个空位。最后一排内容和上拉触发区都能完整滚过底部导航安全区。

底部使用统一系统玻璃 Tab Bar，当前加号图标为填充选中状态，其他图标和标签保持一致。页面没有全身人物、统计主卡、彩色大背景或多余工具入口；重点是快速扫描并点击家务，视觉暗示点击后会打开耗时选择 Sheet。
```

## 3.3 月度战报

### 页面结构

1. 系统 Large Title“月度战报”，右侧无独立阴影的月份控件。
2. 实时领先人物主卡，作为唯一一级视觉锚点。
3. 家庭总积分、完成次数、总耗时次级摘要。
4. 一句平面家庭战报总结。
5. 一个“本月结构”次级容器：四主题圆环 + 家务大类分段比例条和双列图例。
6. 平面成员排行榜。
7. 系统玻璃底部导航，选中“月度战报”。

月报实时更新，不等待月底生成：单人领先显示“本月暂居第一”，同分显示“并列领跑”，全员零分显示“本月战局待开启”，月底结算后显示“本月家庭冠军”。

### 主原型提示词

```text
设计《你今天干啥啦》的“月度战报”主页面。顶部使用系统 Large Title“月度战报”，右上角是轻量系统玻璃月份按钮“2026 年 7 月”与下拉箭头。下方是一张全页唯一的月度荣誉主卡，奶油白或奖章金柔和浅底、22pt 圆角、细描边和轻悬浮阴影。主卡左侧显示标签“本月暂居第一”、成员昵称“王女士”和大数字“486 分”，右侧展示该成员的独立全身人物立绘，1:4 头身比、中度抽象、极简五官；人物不遮挡文字，主卡不制作多人领奖台。

主卡下方使用一行简洁次级摘要，展示“家庭总积分 1280”“完成 42 次”“总耗时 690 分钟”，随后用平面文字给出一句家庭战报总结。再往下只使用一个“本月结构”次级容器：四主题使用圆环显示日常家庭、恋爱陪伴、育儿和宠物的积分占比；家务大类使用一条分段比例条与双列图例，不重复堆叠多条进度卡。

最后是平面“成员排行榜”列表，不使用领奖台或每行独立卡片：每行显示名次、圆形头像、昵称、家庭身份、积分和完成次数；前三名使用金、银、铜小型名次标记，当前用户使用浅色背景与“我”标签，同分显示并列名次。全页只让领跑者卡使用一级阴影，摘要和结构为二级，战报文案和排行无悬浮阴影。底部系统玻璃 Tab Bar 中奖杯图标为填充选中状态。
```

### 实时状态变体提示

```text
同一月度战报页面的零记录状态：保留完整页面结构，冠军主卡改为“本月战局待开启”，展示家庭成员头像或两个小型人物并列等待，不虚构冠军；家庭总积分、次数和耗时均为 0，排行榜显示成员但积分为 0，类型比例区显示轻量说明“记下第一笔后，这里会出现本月分布”。页面不能空白，也不要显示“月报尚未生成”。
```

## 3.4 我的

### 页面结构

1. 不显示顶部“我的”Large Title。
2. 横向身份主卡，依次显示家庭名称、身份、昵称，不显示无行为设置按钮。
3. 邀请码、家庭形象分组，不设置独立“成员状态”行；审核入口仅 OWNER 显示。
4. 可点击的家庭成员列表与近 30 天成员详情；家主转让只放在目标成员详情。
5. 设置与协议分组。
6. Debug 区默认折叠，仅 Debug 显示。
7. 页面底部退出登录。
8. 系统玻璃底部导航，选中“我的”。

### 主原型提示词

```text
设计《你今天干啥啦》的“我的”主页面。不要显示顶部“我的”大标题，页面从安全区下方直接以横向身份主卡开场。主卡为全页唯一彩色重点，左侧展示 72-80pt 的人物头像裁切，右侧依次显示加粗家庭名称“今日劳动观察站”、家庭身份“男主人”和昵称“用户 123456”。不放无明确行为的设置按钮；OWNER 点击家庭名称可编辑，MEMBER 只读。主卡使用轻描边和柔和阴影，不使用粗黑框。

身份卡下方全部使用白色分组列表。第一组显示等宽邀请码“A5F637F7”和家庭形象，邀请码提供复制与系统分享，不显示数据库 familyId，也不设置独立“成员状态”行。只有 OWNER 显示“审核加入申请”入口和待处理数量 Badge。随后是家庭成员头像横排或紧凑列表，头像无额外白色外圈，昵称下方显示身份，OWNER 用头像右下角皇冠表达。点击其他 ACTIVE 成员进入滚动近 30 天动态详情；仅 OWNER 查看另一位 MEMBER 时显示“转让一家之主”。

第二组包含当前套餐、用户协议和隐私政策；Profile 不显示图片凭证、成员状态或其他未开放功能的占位行。Debug 区位于靠下位置、默认折叠、视觉弱化且标注仅开发模式。页面最底部是珊瑚红文字按钮“退出登录”，不使用大红色卡片。底部统一系统玻璃 Tab Bar 中人像图标为填充选中状态。整体是四个主页面中最安静、最接近系统设置体验的页面。
```

## 4. 配套小页面与状态提示词

这些页面不需要与四个主页面同时生成，但应复用同一套字体、圆角、描边、玻璃、人物和语义色。

## 4.1 Login 登录首页

```text
设计《你今天干啥啦》的 iPhone 登录首页。它是全 App 漫画感最强的页面：顶部品牌大标题“你今天干啥啦”，副标题“今天这活，到底谁干了？”，中部是简洁但有冲击力的夫妻家务大战扁平插画，人物中度抽象、锅碗、拖把、抹布和衣物形成动态构图，但不出现真实伤害。页面下半部分清楚排列三个大按钮：亮黄“手机号登录”、天蓝“微信登录 · 即将支持”、奶油白“Apple 登录 · 即将支持”，按钮使用细深色描边和少量品牌硬阴影。底部是协议复选框、“用户协议”和“隐私政策”。保证三个按钮和协议在小屏可操作，必要时缩小插画，不把页面做成纯海报。
```

## 4.2 CreateFamily 创建家庭

```text
设计《你今天干啥啦》的“创建家庭”单页三段式表单。顶部使用系统紧凑导航和清楚标题“创建家庭”。第一段是家庭名称输入框；第二段是可左右滑动的三卡人物轮播，中间展示当前可选择的完整全身立绘，左右各展示一张缩小预览，从 13 个固定成员形象中选择，并显示当前位置如“7 / 13”。中间选中卡使用人物主色的低饱和浅底、1.5pt 轻描边、柔和阴影和勾选状态，左右滑动时分页吸附。第三段是家庭身份选择，包括男主人、女主人、老公、老婆、老妈、老爸、儿子、女儿、哥哥、姐姐、弟弟、妹妹、爷爷、奶奶、室友、自定义，选择自定义时显示输入框。图片凭证以浅色提示“即将开放”，开关不可开启。底部固定亮黄“创建家庭”按钮，页面可滚动，不拆成多步，不使用大面积漫画插画。
```

## 4.3 CreateFamilySuccess 创建成功与邀请码

```text
设计《你今天干啥啦》的“家庭创建成功”结果页。顶部使用系统成功图标和标题“家庭建好了”，中间是一张轻量邀请码主卡，显示家庭名称“今日劳动观察站”和等宽大字邀请码“A5F637F7”，提供“复制邀请码”和系统分享两个清楚按钮，并用短文案说明“让家人用邀请码申请加入”。下方显示当前用户头像、家庭身份和“一家之主”Badge。主按钮为“选择常用家务”，进入四主题家务库；次按钮为“稍后邀请”。不要显示数据库 familyId，不生成二维码、邀请海报或复杂庆祝动画。
```

## 4.4 JoinFamily 申请加入家庭

```text
设计《你今天干啥啦》的“加入家庭”页面。顶部使用系统紧凑导航标题，首先是醒目的家庭邀请码输入框，示例“A5F637F7”，提供明确错误 Banner 区域。下面依次为可左右滑动的三卡人物轮播和家庭身份选择：中间展示当前可选择的完整全身立绘，左右为缩小预览，从 13 个固定成员形象中选择，并显示当前位置如“8 / 13”；自定义身份按需展开输入框。底部固定亮黄“提交加入申请”按钮，并提供弱化的“返回”或“切换账号”。页面说明使用邀请码加入，不出现数据库 familyId、二维码扫描或复杂邀请链接功能。
```

## 4.5 JoinPending 等待审核

```text
设计《你今天干啥啦》的“等待审核”状态页。页面保持大量奶油白留白，中间是一张白色轻悬浮状态卡，展示当前人物头像、申请加入的家庭名称、所选身份和状态 Badge“等待一家之主审核”。配一张小型静态人物等待插画裁切和文案“申请已经送达，先等一家之主点头。”。底部提供“刷新状态”主按钮和弱化“切换账号”。不要显示家庭数据、家务网格或虚假进度条，不做持续动画。
```

## 4.6 JoinRequests OWNER 审核加入

```text
设计《你今天干啥啦》的 OWNER 次级页面“加入申请”。顶部使用系统紧凑导航标题和返回按钮，不显示 Large Title。白色分组列表按时间倒序展示申请人，每行包含 48pt 人物头像、昵称、申请身份和申请时间，右侧提供薄荷绿轻按钮“通过”和珊瑚红文字按钮“拒绝”。列表行平面并使用分隔线，不为每行添加独立卡片阴影。无申请时显示一个静态人物头像裁切、文案“暂时没有新的加入申请”和返回入口。拒绝确认由系统 confirmationDialog 承担，不在页面常驻漫画弹窗。
```

## 4.7 ActivityAll 全部家庭动态

```text
设计《你今天干啥啦》的次级页面“家庭动态”。顶部使用系统紧凑导航标题、返回按钮和轻量范围筛选“今日 / 最近”。主体为单个白色分组列表，按时间倒序展示完整动态。每行包含成员头像、身份与昵称、家务名称、实际耗时、积分、完成时间、拇指点赞图标、点赞数量以及最多 3 个点赞成员小头像和“+N”。已点赞为亮黄填充，可删除的记录保留 iOS 左滑删除能力但默认画面不展开。页面没有底部四 Tab，不为每行添加悬浮卡片，长列表保持安静可扫描。
```

## 4.8 ChoreDurationPickerSheet 实际耗时

```text
设计覆盖在“记一下”页面上的 iOS 系统半高 Sheet。Sheet 带拖拽指示器和轻玻璃材质，顶部只显示家务小图标和名称“清理卫生间”，不要出现“系统建议”文字。中间是类似 iOS 闹钟的单列分钟滚轮，当前选择“20 分钟”，上下可见相邻分钟。滚轮下方是一张紧凑白色积分卡，使用亮黄局部高光显示“预计 +20 分”。底部是亮黄主按钮“确认记录”和弱化文字按钮“取消”。小屏允许内部滚动，不写死高度，不使用粗描边、爆炸框或大插画。
```

## 4.9 LaunchLoading 启动恢复登录

## 4.10 Error / Offline / Empty 状态组件页

```text
设计《你今天干啥啦》的状态组件展示页，奶油白背景，纵向展示三种真实 App 状态：浅珊瑚错误 Banner，包含警示图标、简短错误和“重试”；轻量离线提示，说明正在展示已有数据；空状态卡，包含一个家庭成员头像或半身裁切、一句幽默但克制的文案和一个明确主按钮。所有状态使用系统字体、细描边和轻阴影，不使用爆炸框、闪烁骨架屏、技术错误堆栈或大面积红色背景。
```

## 6. 原型审阅顺序

建议优先审阅：

1. `Week_Default_本周战况`：验证周统计信息密度和互动结构。
2. `Record_Default_记一下`：验证家务卡片体系能否长期扩展。
3. `DurationPicker_Default_实际耗时`：验证系统感与品牌感的平衡。
4. `Monthly_LiveLeader_月度战报`：验证全身人物与数据是否抢占彼此。
5. `Profile_OWNER_我的`：验证克制风格能否仍保持品牌识别。

审阅时逐项检查：

- 是否约 80% 为白色或奶油色。
- 是否只有一张视觉主卡。
- 是否误用了固定页面分区色。
- 功能页描边和阴影是否过重。
- 四个 Tab 图标、顺序、标签和选中状态是否统一。
- 人物是否来自同一套 6 人体系。
- 系统 Large Title 是否只出现在今日、记录和月报。
- “我的”是否直接以横向身份卡开场。
- 月报是否展示实时领先状态而不是“尚未生成”。
- 小屏安全区、长文字、滚动内容和按钮是否真实可用。
